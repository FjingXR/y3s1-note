Chapter 5 — Storage

Everything about how data is stored, protected, and secured in IT infrastructure. From hard disks to RAID, backups to encryption.

MODULE 5.1

Storage building blocks

Slides 12–16

Every IT system stores data. Before understanding complex storage, you need to know the basic building blocks.

Q1. What is the storage model?

Answer

The storage model shows how infrastructure is organized:

  • Functional Management — process/information layer
  • Application Management — application layer
  • Platform Management — application platform
  • Infrastructure Management — compute, storage, networking, datacentres

Storage sits at the infrastructure layer — it's the foundation everything else builds on.

Q2. What is DAS (Direct Attached Storage)?

Answer

DAS = disks that connect directly to a server via SAS or SATA cables, through a built-in controller on the PCI bus. The OS sees these as local disk blocks organized into LUNs (partitions).

Q3. How do disks communicate with the server?

Answer

Disks use a command set to talk to disk controllers. The main ones:

ProtocolFull NameKey Feature
ATA / IDEAdvanced Technology AttachmentOld, simple, slow. Connected via ribbon cables.
SCSISmall Computer System InterfaceFaster, more reliable. Used in servers.
SATASerial Advanced Technology AttachmentSerial version of ATA. Faster, thinner cables. Common in consumer PCs.
Remember

ATA/IDE = old and slow. SCSI = server-grade. SATA = modern consumer. All of these connect disks to controllers via command sets.

Storage Media

Storage media types

Slides 21–39

There are 3 main types of storage media: mechanical hard disks, solid-state drives, and tapes. Each has different strengths.

Q1. What are the types of mechanical hard disks?

Answer

  • SATA disks — cheapest, good for general use
  • NL-SAS (Near-Line SAS) — has a SAS interface but SATA mechanics. Can mix with faster SAS disks in one array.
  • SAS disks — fastest mechanical disks, used in enterprise servers

Q2. What are the advantages and disadvantages of SSDs?

Answer

See cards below.

SSD Advantages

  • Consume less power
  • Generate less heat
  • No moving parts — no vibrations
  • Prices have dropped significantly

SSD Disadvantages

  • Limited life expectancy (write cycles)
  • Slower than NVMe drives
  • Higher cost per GB than HDD

SATA SSD

Uses the SATA interface. Cheapest SSD. Good upgrade from HDD.

M.2 SSD

Smaller form factor, plugs directly into motherboard. Faster than SATA SSD.

NVMe SSD

Uses Nonvolatile Memory Express protocol. Fastest SSD type. Direct connection to CPU via PCIe.

Q3. What is Kryder's law?

Answer

Kryder's law states that disk capacity doubles approximately every two years (similar to Moore's law for CPUs). The vertical scale is logarithmic. To benefit fully, storage infrastructure should be designed for just-in-time expansion.

Q4. What are tapes used for?

Answer

  • Large amounts of data — very high capacity
  • Inexpensive — lowest cost per GB
  • Archiving — long life expectancy
  • Disadvantages: fragile, mechanical parts, frequent rewinding causes stress, slow sequential access
LTO tape facts

LTO (Linear Tape Open) has 80%+ market share. LTO-9 stores 18 TB uncompressed. Throughput: ~200 MB/s sustained, up to 700-900 MB/s with Fibre Channel interface.

Which storage type has the lowest cost per GB?

Controllers

Controllers & virtual disks

Slides 40–42

Controllers connect disks to servers. They can split disks into smaller pieces and create virtual disks.

Q1. How do controllers connect to servers?

Answer

  • PCI expansion board — installed directly in the server
  • NAS or SAN deployment — connects all disks/tapes via Fibre Channel, iSCSI, or FCoE connections

Q2. What can a controller do?

Answer

  • High performance
  • High availability
  • Virtualized storage
  • Cloning
  • Data deduplication
  • Thin provisioning

Q3. What are physical extents and LUNs?

Answer

The controller splits all disks into small pieces called physical extents. From these, new virtual disks (LUNs — Logical Unit Numbers) are composed and presented to the operating system.

Disk 1 & Disk 2 Physical extents (raw disk blocks)
Controller Combines physical extents into logical extents
LUN (Virtual Disk) Presented to the OS as a single disk

RAID

RAID levels EXAM

Slides 43–52

RAID (Redundant Array of Independent Disks) uses multiple disks to provide high availability and better performance. There are 5 main RAID levels.

Q1. What are the 5 common RAID levels?

Answer

  • RAID 0 — Striping: data split across disks. Fast, but no redundancy. Lose 1 disk = lose all data.
  • RAID 1 — Mirroring: exact copy on 2 disks. Most reliable. Expensive (50% space used).
  • RAID 10 — Striping + Mirroring: combo of RAID 0 + 1. High performance AND availability. 50% space used.
  • RAID 5 — Striping with distributed parity: parity blocks spread across disks. Can survive 1 disk failure. Good balance.
  • RAID 6 — Striping with double parity: two parity blocks. Can survive 2 disk failures simultaneously.
RAID LevelTypeMin DisksUsable SpaceFault Tolerance
RAID 0Striping2100%None
RAID 1Mirroring250%1 disk
RAID 10Stripe + Mirror450%1 per mirror pair
RAID 5Stripe + Parity3N-11 disk
RAID 6Stripe + Double Parity4N-22 disks

Q2. What is the RAID write penalty?

Answer

Writing data on multiple disks introduces delay called the RAID penalty:

RAID LevelWrite Penalty
RAID 00 (no penalty)
RAID 12
RAID 102
RAID 54
RAID 66
Common mistake

RAID 0 has NO redundancy. If one disk fails, ALL data is lost. Only use RAID 0 for temporary data where loss is acceptable.

Which RAID to pick?

Need speed, no redundancy → RAID 0. Need max reliability → RAID 1. Need both speed + reliability → RAID 10. Need good balance → RAID 5. Need double-disk fault tolerance → RAID 6.

More practice

Which RAID level is the most reliable?
RAID 1 (Mirroring) — creates an exact copy, most reliable but expensive.
How many disks can fail in RAID 5?
Only 1 disk. RAID 5 uses distributed parity to survive a single disk failure.
What percentage of disk space is usable in RAID 10?
50% — half the space is used for mirroring.
Data Services

Data services

Slides 53–64

Storage controllers provide extra data services: compression, deduplication, cloning, snapshots, and thin provisioning.

Q1. What is data compression?

Answer

Data on disk and tape is typically stored compressed. It allows 2 to 2.5x more data on the same media. The compression ratio depends on how diverse the data is — more diverse = lower compression.

Q2. What is data deduplication?

Answer

Deduplication searches for duplicate data segments (disk blocks or files) and removes them. Instead of storing duplicates, it creates a pointer to the existing data.

How it works: Segments incoming data → calculates hash tags → compares with existing hashes → if duplicate, creates pointer instead of storing again.

MethodHow It WorksProsCons
Inline dedupChecks for duplicates BEFORE writing to diskNo duplicate data on disks at any timeLarge performance penalty
Periodic dedupWrites first, checks periodically for duplicatesNo performance hit during writesDuplicate data stays on disk for some time

Q3. What is the difference between cloning and snapshots?

Answer

See comparison table below.
FeatureCloningSnapshots
ScopeFull copy of the diskPoint-in-time image of data
Time to createTime-consumingQuick
ReversibilityComplexEasy
Use casesCreating new VMs, restoring from backupsBackups, testing, recovery

Q4. What is thin provisioning?

Answer

Thin provisioning allocates more storage to users than physically installed. About 50% of allocated storage is never used. The system monitors real usage and adds physical disk space only when needed. Typical use: large home directories or email storage.

Where to find it

More practice

What is the typical compression ratio?
2 to 2.5 times more data on the same media.
Which dedup method has better performance but keeps duplicates temporarily?
Periodic dedup — writes first, checks later for duplicates.
Network Storage

Network storage types EXAM

Slides 65–85

There are 3 main ways to provide storage over a network: DAS, SAN, NAS, plus Object Storage and Software Defined Storage.

Q1. What is the difference between DAS, SAN, and NAS?

Answer

See table below.
FeatureDASSANNAS
Full nameDirect Attached StorageStorage Area NetworkNetwork Attached Storage
ConnectionSAS/SATA directly to serverFibre Channel, iSCSI, FCoETCP/IP (SMB/CIFS, NFS)
What it offersDisk blocks (LUNs) to 1 serverDisk blocks (LUNs) to multiple serversShared file system to multiple servers
AccessBlock-levelBlock-levelFile-level
Use caseLocal server storageEnterprise databases, VMsShared files, documents

Q2. What is SAN and how does it work?

Answer

A SAN is a specialized storage network with SAN switches (the Fabric), HBAs (Host Bus Adapters in servers), and disk arrays.

Servers connect to SAN switches via HBAs (like NICs for storage). Disk controllers offer virtual disks (LUNs) to servers through the SAN. A disk array can contain several petabytes of data.

Q3. What are the SAN connectivity protocols?

Answer

See cards below.

Fibre Channel (FC)

Dedicated Level 2 protocol for storage. Speeds: 1 to 128 Gbit/s. Runs on copper or fiber optic. Guaranteed zero data loss. 3 topologies: Point-to-Point, Arbitrated Loop, Switched Fabric.

FCoE

Fibre Channel over Ethernet. Encapsulates FC in Ethernet packets. Needs 10 Gbit+ Ethernet with lossless extensions (DCB/CEE). Uses CNAs (Converged Network Adapters).

iSCSI

SCSI over Ethernet LAN using TCP/IP. Uses familiar TCP/IP protocols. Lower performance than FC due to TCP/IP overhead. Growing fast with 10/40 Gbit Ethernet.

Q4. What is the difference between SAN and NAS?

Answer

  • SAN: offers disk blocks (LUNs), uses iSCSI/FC/FCoE, only one server can mount a specific LUN
  • NAS: offers shared file system, uses SMB/CIFS or NFS over TCP/IP, multiple servers can access files, connects to LDAP/Active Directory for permissions

Q5. What is Object Storage?

Answer

Object storage manages data as objects accessed via REST API over HTTP. Highly scalable. Used by cloud providers: AWS S3, Azure Blob Storage, GCP Object Storage.

Key fact: Data in object storage cannot be modified. To change a file, the original is deleted and a new one is created. Good for: office documents, backups, archives, video/audio, VM images.

Q6. What is Software Defined Storage (SDS)?

Answer

SDS abstracts storage management (control plane) from physical storage (data plane). It virtualizes all physical storage into one shared pool. Can run on commodity x86 servers with DAS, or on SAN/NAS/Object storage. Provides data services like dedup, compression, caching, snapshots, cloning, replication, and tiering.

Cloud storage is SDS

All major cloud providers (AWS, Azure, GCP) use SDS for their storage services. APIs let you provision, monitor, and manage your own storage.

Where to find it

C5 Storage.pdf — slides 65 to 85 (DAS, SAN, NAS, Fibre Channel, FCoE, iSCSI, Object Storage, SDS).

More practice

Which storage type offers a shared file system over TCP/IP?
NAS (Network Attached Storage) — uses SMB/CIFS or NFS protocols.
Why can't you modify a file in object storage?
Object storage is designed for immutable data. To change a file, you delete the old one and create a new one.
What does FCoE stand for?
Fibre Channel over Ethernet — encapsulates Fibre Channel data in Ethernet packets.
Availability

Storage availability

Slides 86–94

Storage availability = how often your storage system is accessible. Redundancy and replication increase availability.

Q1. How do you increase storage availability?

Answer

  • Install redundant components (HBAs, switches)
  • Use multiple paths between HBAs and SAN switches (automatic failover)
  • Use multiple storage systems with replication (continuous copy of data to secondary system)

Q2. What is the difference between synchronous and asynchronous replication?

Answer

See table below.
FeatureSynchronous ReplicationAsynchronous Replication
How it worksWrite to primary AND secondary must complete before write is confirmedWrite to primary is confirmed immediately, secondary gets data later
Time difference0 ms (real-time)> 0 ms (has a lag)
Data safetyData is always synchronized — no data lossPotential data loss if primary fails before secondary is written
PerformanceSlower (must wait for both writes)Faster (primary write confirmed immediately)
Distance limit~100 km max (latency too high beyond)No distance limit
RiskIf connection fails, primary cannot writeData loss window between primary and secondary writes
Common mistake

Replication does NOT protect against data erasure or corruption from software bugs. If data is deleted or corrupted, the bad data is also replicated. That's why you still need backups.

Where to find it

C5 Storage.pdf — slides 86 to 94 (Availability, Redundancy, Synchronous vs Asynchronous Replication).

More practice

What is the main advantage of synchronous replication?
Data is always synchronized between primary and secondary — no data loss possible.
Why can't synchronous replication work over 100 km?
Latency becomes too high, slowing down applications that must wait for both writes to complete.
Backup & Recovery

Backup & recovery EXAM

Slides 95–118

Backups are copies of data used to restore data after loss, corruption, or disaster. They are a last resort when everything else fails.

Q1. What is the 3-2-1 backup rule?

Answer

  • Keep 3 copies of your data
  • On 2 different media types
  • With 1 copy stored at a separate location

Q2. What are the 5 backup schemes?

Answer

See cards below.

1. Full Backup

Complete copy of all data. Takes most time/space. Easiest to restore. Done at large intervals (weekly/monthly).

2. Incremental Backup

Only saves data changed since the last backup (any type). Small backup size. Slowest to restore (must replay all increments).

3. Differential Backup

Only saves data changed since the last full backup. Faster to restore than incremental (full + last differential only).

4. Incremental Forever

Initial full backup, then only incremental forever. Metadata lets the system compile point-in-time restores from increments.

5. CDP

Continuous Data Protection. Every change is simultaneously backed up. RPO = zero. Expensive, used in critical environments only.

Q3. What is the GFS backup schedule?

Answer

Grandfather-Father-Son (GFS) is a retention schedule:

  • Son (Daily) — backup made every day
  • Father (Weekly) — after a week, oldest daily becomes weekly
  • Grandfather (Monthly) — after 4 weeks, oldest weekly becomes monthly

Daily backups from previous weeks are deleted. This keeps a rotating window of backups.

Q4. What is the difference between backup and archiving?

Answer

See table below.
FeatureBackupArchiving
PurposeProtection against data lossLong-term storage for compliance/regulations
RetentionShort-term (weeks)Long-term (years, even decades)
Data statePoint-in-time copy for restoreRead-only, cannot be modified
ExampleDaily backup of databaseMedical records kept 30 years after death
Backup best practices
  • Test restore procedure at least once a year
  • Keep backups at least 5 km from main site
  • Also store: OS installation disks, license keys, printed restore procedures
  • Test restore monthly to verify media still works

Q5. What is archiving and why is it important?

Answer

Archiving is done for compliance and regulation. Example: US law requires medical records kept 30 years after death (X-rays at birth = 130 years!).

Archived data is read-only to prevent alteration. Some systems use WORM (Write Once Read Many) media like CD/DVD/Blu-ray or WORM tapes.

Key rules: Use open standards, store in human-readable formats (XML), transfer to latest media every 10 years.

Noncompliance consequences

Not following data retention laws can lead to serious business disruption, fines, and even jail time. Examples: HASIL (Malaysia tax), Bank Negara Malaysia (AML/CFT records).

More practice

What does RPO mean in CDP?
Recovery Point Objective. In CDP, RPO is set to zero because every change immediately triggers a backup.
Which backup scheme is fastest to restore?
Full backup — only one file to restore (no need to replay multiple increments).
What does WORM stand for?
Write Once Read Many — data can be written once but cannot be modified or deleted. Used for archival compliance.
Performance

Storage performance

Slides 119–134

Storage performance depends on disk speed, interface throughput, caching, and tiering.

Q1. What affects disk performance?

Answer

  • Disk rotation speed — max ~15,000 RPM (at this speed, edge of 3.5" disk moves at 250 km/h!)
  • Seek time — time for head to reach the right track. 3ms (high-end) to 9ms (low-end)
  • Interface protocol — how fast data moves from disk to server

Q2. What is caching?

Answer

A caching system in disk controllers improves performance by orders of magnitude.

  • Read-cache — acts as buffer for reads. Same data served from cache on repeat reads.
  • Write-through cache — data written to cache first, then to disk. Write acknowledged when data is in cache (fast). Cache buffers writes, disk writes when ready.

Q3. What is storage tiering?

Answer

Tiered storage creates a hierarchy based on cost, performance, and availability requirements:

Tier 1 — Production Data SSD and SAS disks (highest performance)
Tier 2 — Seldom Used Data Email archives (NL-SAS disks)
Tier 3 — Backup Virtual Tape Libraries on NL-SAS
Tier 4 — Archival Tape or NL-SAS disks (lowest cost)
Cloud storage tiers

Storage tiering is especially important in the cloud — different tiers have very different costs (e.g., Google Cloud charges more for high-performance tiers).

Where to find it

C5 Storage.pdf — slides 119 to 134 (Disk Performance, IOPS, RAID Penalty, Caching, Storage Tiering).

More practice

What is the max rotation speed for disks?
About 15,000 RPM — going faster would physically destroy the disk.
What is the difference between read-cache and write-through cache?
Read-cache buffers repeated reads from cache. Write-through cache writes to cache first (fast), then to disk when ready.
Security

Storage security

Slides 135–144

Storage security means protecting data at rest (on disk) and controlling who can access storage on a SAN.

Q1. How do you protect data at rest?

Answer

Data can be in transit, in use, or at rest (stored on disk). Data at rest is protected using encryption.

Why encrypt in the datacenter?

  • Disks might get into wrong hands
  • Failed disks must be returned to vendors — encryption prevents data exposure
  • Full disk encryption makes it harder to recover data from "empty" disk space

Q2. What are Self-Encrypting Drives (SEDs)?

Answer

SEDs have encryption built into the disk hardware. When powered up, authentication is required (password to boot). Encryption keys are stored on the disk itself. Used in laptops and desktops.

Q3. What is Cryptographic Disk Erasure (CDE)?

Answer

CDE deletes the encryption key on the disk. Without the key, unencrypted data can no longer be read. It's one of the best ways to fully wipe a disk's contents.

Q4. What is SAN zoning?

Answer

SAN zoning arranges Fibre Channel devices into logical groups on the SAN fabric for security. Devices can only communicate if they are in the same zone. Similar to VLANs in Ethernet networks. Implemented in SAN switches.

Q5. What is LUN masking?

Answer

LUN masking makes a LUN available to some hosts and unavailable to others. Implemented at the HBA level (not in SAN switches). Best practice: use both SAN zoning AND LUN masking together.

FeatureSAN ZoningLUN Masking
What it controlsWhich FC devices can see each otherWhich LUNs a specific host can access
Implemented atSAN switchesHBA level (in the server)
AnalogyLike VLANs in EthernetLike file permissions
Best practice

Always use a combination of SAN zoning AND LUN masking for maximum security. Zoning limits which devices can talk; masking limits which storage each device can use.

Where to find it

C5 Storage.pdf — slides 135 to 144 (Storage Security, Data at Rest, SEDs, CDE, SAN Zoning, LUN Masking).

More practice

What is the best way to wipe a disk clean?
Cryptographic Disk Erasure (CDE) — delete the encryption key. Without it, data cannot be read.
Where is SAN zoning implemented?
In the SAN switches — devices can only communicate if they are in the same zone.
What is the difference between SAN zoning and LUN masking?
SAN zoning controls which FC devices can see each other (at switch level). LUN masking controls which LUNs a host can access (at HBA level).

One-paragraph recap

  • Storage building blocks include DAS and disk command sets (ATA/IDE, SCSI, SATA).
  • 3 media types: HDD (moving parts, cheapest per GB), SSD (no moving parts, faster), Tape (sequential, archival, cheapest per GB).
  • RAID provides redundancy: RAID 0 (stripe, no protection), RAID 1 (mirror), RAID 10 (both), RAID 5 (parity), RAID 6 (double parity).
  • Data services: compression (2-2.5x), deduplication (remove duplicates), cloning (full copy) vs snapshots (point-in-time), thin provisioning (allocate more than physically installed).
  • Network storage: DAS (direct), SAN (block-level network, FC/iSCSI/FCoE), NAS (file-level, SMB/NFS), Object Storage (REST API, immutable), SDS (abstracted pool).
  • Availability: redundancy (extra components), synchronous replication (real-time, ≤100km) vs asynchronous (has lag, faster, no distance limit).
  • Backup: 3-2-1 rule (3 copies, 2 media, 1 offsite). Schemes: full, incremental, differential, incremental forever, CDP. GFS retention schedule.
  • Backup ≠ Archive. Backup protects from data loss (short-term). Archive is for compliance (long-term, read-only).
  • Performance: disk speed limits (15K RPM), caching (read/write-through), storage tiering (Tier 1-4 hierarchy).
  • Security: encrypt data at rest (SEDs, CDE), SAN zoning (logical groups), LUN masking (host-level access control).

Common mistakes to avoid

  • Confusing backup with archive — backup is for data loss protection, archive is for compliance.
  • Thinking replication replaces backups — replication copies bad data too (deleted/corrupted).
  • Forgetting RAID 0 has NO redundancy — lose 1 disk, lose all data.
  • Confusing synchronous (real-time, slower) with asynchronous (has lag, faster) replication.
  • Thinking SAN and NAS are the same — SAN offers blocks, NAS offers files.
  • Forgetting that object storage data cannot be modified — must delete and recreate.
