# **1.0 Storage Building Block**

## **1.1 Existing Implementation and Impact**

| **Existing Implementation** | **Identified Issues** | **Impact on Business Operations** |
|---|---|---|
| Servers at headquarters in Kota Kinabalu use **Direct Attached Storage (DAS)** with internal SATA hard disks. Storage expansion is done reactively and disks are added only when capacity alerts are triggered. | DAS offers **no centralized storage management**. Each server manages its own disks independently. No capacity forecasting exists and this forces emergency disk purchases at higher prices when storage runs out. | IT staff waste time on manual data migration between servers. Emergency expansion requires taking servers offline and this causes unplanned service disruption and budget overruns. |
| The company uses **RAID 5** for data protection across its internal server disks. | RAID 5 writes incur a **performance penalty of 4 IOPS per write operation**. During festive seasons and sales promotions the storage subsystem becomes a bottleneck. | Customers experience longer POS checkout times and slower online page loading. Inventory records lag behind actual sales and this leads to overselling during peak periods. |
| **Backup is performed weekly** using external USB hard drives connected manually to the main server. Backup drives are stored in the same server room at the Kota Kinabalu headquarters. **No replication or snapshots** are implemented and the system relies solely on RAID 5 for fault tolerance. | The weekly backup creates a **Recovery Point Objective (RPO) of up to 7 days**. RAID protects against disk failure but not against data corruption, accidental deletion, or software bugs. On-site backups share the same disaster risk as the primary data. | A server failure could lose an entire week of sales transactions, inventory changes, and customer orders. A fire, flood, or break-in at headquarters would destroy both primary data and backup copies at the same time. |
| **No storage tiering, data deduplication, or compression** is in place. All data including critical transactional databases and archived sales reports is stored on the same type of SATA disks. | Business-critical applications share the same performance tier as archival data and this causes **I/O contention** when batch jobs run during business hours. Identical data blocks consume duplicate disk space and waste capacity. | POS transaction processing slows down during end-of-day reporting. Storage costs per GB are higher because more disks are needed than necessary. Backup windows are longer due to larger data volumes. |
| Data is stored in **unencrypted format** on internal server disks. | Physical theft of servers or disposal of failed hard disks could expose customer personal information, payment records, and supplier data. This would violate Malaysia's **Personal Data Protection Act (PDPA) 2010**. | Non-compliance with PDPA 2010 risks legal penalties and reputational damage. Failed disks returned to vendors under warranty cannot be securely erased and may contain residual customer data. |

## **1.2 Proposal and Justification**

| **Proposed Solution** | **Justification (How It Resolves the Issue)** | **Alignment with Company Constraints, Malaysian Market Challenges, and Business Value** |
|---|---|---|
| Deploy a **Storage Area Network (SAN)** with dual redundant Fibre Channel (FC) controllers at 16 Gbit/s and connect all servers via dual Host Bus Adapters for path redundancy. Enable **thin provisioning** to allocate storage on demand. Implement centralized monitoring for IOPS, latency, and capacity forecasting. | A SAN eliminates DAS silos by pooling all storage into a single fabric where LUNs are dynamically provisioned to any server. Thin provisioning prevents over-allocation because about 50% of allocated storage is never used so physical capacity is consumed only as data is actually written. Monitoring replaces reactive emergency expansion with planned upgrades. | SAN is cost-effective for a 10-branch retail operation with centralized IT management. It reduces administrative overhead by consolidating storage under one console. Fibre Channel delivers sub-1 ms latency compared to 8 to 12 ms on DAS SATA and this enables faster POS processing and a smoother online shopping experience for Malaysian customers. Capacity forecasting avoids emergency purchases and unplanned downtime. |
| Configure **RAID 10 (striping plus mirroring)** using SAS SSDs for the database LUNs hosting POS transactions, inventory management, and customer databases. | RAID 10 has a **RAID penalty of only 2** compared to RAID 5 penalty of 4 and this doubles write IOPS for transaction-heavy workloads. If a disk fails the mirrored copy continues serving data instantly with no performance degradation. | RAID 10 is well-suited for the company most performance-critical workloads. Upgrading only the database LUNs limits cost while targeting the bottleneck. During festive seasons like Hari Raya and Chinese New Year POS throughput improves 80 to 100 percent and this reduces checkout time and prevents lost sales. |
| Deploy a **Virtual Tape Library (VTL)** on NL-SAS disks for daily backups and **LTO-9 tape cartridges** for weekly full backups stored off-site in Kuching. Implement **Grandfather-Father-Son (GFS)** rotation with automated scheduling. Enable **hourly snapshots** and **asynchronous replication** of critical LUNs to the Kuching DR site every 15 minutes. | The 3-2-1 rule is satisfied with three copies, two media types, and one copy off-site. Snapshots provide instant point-in-time recovery from corruption or accidental deletion. Asynchronous replication sends only changed blocks to Kuching and this achieves sub-15-minute RPO without impacting production write performance. | Automated backup eliminates reliance on manual USB drives. Off-site tape in Kuching provides geographic diversity across Sabah and Sarawak and this protects against localized disasters. Asynchronous replication tolerates East Malaysia intermittent inter-region network connectivity better than synchronous replication. RPO improves from 7 days to 15 minutes for critical data. |
| Configure **automated storage tiering** on the SAN with Tier 1 using SAS SSD for hot data, Tier 2 using SAS HDD for warm data, and Tier 3 using NL-SAS HDD for cold data. Enable **inline data deduplication and compression** on the SAN controller. | Tiering moves frequently accessed data to high-performance SSDs while cold data migrates to cost-effective NL-SAS disks and this eliminates I/O contention. Deduplication uses hash tag comparison to replace duplicate blocks with pointers and compression reduces unique block sizes to achieve 40 to 60 percent storage reduction. | Tiering delivers SSD performance for active retail data without purchasing all-flash capacity for the entire footprint. It achieves 60 to 70 percent of all-flash performance at 40 to 50 percent of the cost. Deduplication is especially effective for retail product catalogs with identical images shared across categories. Storage utilization improves 2 to 3 times and this reduces cost per effective terabyte. |
| Deploy **Self-Encrypting Drives (SEDs)** with AES-256 hardware encryption across all tiers. Use **Cryptographic Disk Erasure (CDE)** for decommissioning failed or replaced drives. | SEDs encrypt data at rest with zero performance overhead. If a disk is physically removed the data cannot be accessed without the encryption key. CDE deletes the encryption key instantly and this renders all data unreadable so failed drives can be securely returned to vendors under warranty. | SEDs provide a demonstrable control for Malaysia PDPA 2010 compliance without operational overhead. Customer personal data collected through the online platform is protected even if disks are stolen or improperly disposed. This strengthens customer trust in the company digital services and supports business growth. |
