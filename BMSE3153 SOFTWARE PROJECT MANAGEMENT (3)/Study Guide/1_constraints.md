# 1. Project Constraints (Scenario-Based)

## The Triple Constraints
Every Project Manager (PM) faces **three major constraints** (Chp1, slide 9). The PM's mantra is:

> "To develop a system **on time, within budget, and to the required quality**."

| Constraint | What it means | Typical scenario clues |
| --- | --- | --- |
| **Time** | Project must finish by a deadline | "within 3 months", "by 01-05-2026", a fixed launch date |
| **Cost (Budget)** | Spending must stay within the approved amount | "allocated budget of RM180,000", "not more than $100,000" |
| **Quality / Scope** | Deliverables must meet required features & standards | listed modules/features, "reduce booking time to 10 mins", sales/accuracy targets |

> Note: Scope and Quality are linked — the required *features* (scope) define what "good enough" (quality) means. The lecture also lists **Resources** as a common constraint (staff, equipment, materials).

## Other Challenges a PM Faces (use to justify answers)
From Chp1, slide 10 — when a scenario describes problems, these are the usual culprits:
- Resource constraints (too few staff, waiting for hardware/software)
- Scope changes / changing user requirements
- Deadline pressure / impossible deadlines
- Poor estimates and plans
- Lack of communication / skill / standards
- Preceding activities not completed on time

## How to Answer a "Identify Constraints From a Scenario" Question
1. Read the scenario and underline every **number tied to time, money, features, or people**.
2. Map each to a constraint type (Time / Cost / Scope / Resource / Quality).
3. For each constraint you name, **quote the clue** and explain why it limits the PM.

## Worked Example — Tutorial 1, Question 2 (T-Shirts2U)
**Scenario:** Develop a new online ordering system to increase annual sales by RM50,000. Modules: Customer, Order carts, Online payment, Order fulfillment. Must be completed **within 3 months** with an **allocated budget of RM180,000**. Team = **six software developers**.

### (a) Identify and explain TWO (2) constraints
**Constraint 1 — Time.**
The project must be completed within 3 months. This is a time constraint because the PM must schedule all tasks (requirements, design, coding, testing, deployment) to finish inside this fixed window; any delay risks missing the deadline.

**Constraint 2 — Cost (Budget).**
The allocated budget is RM180,000. This is a cost constraint because all development effort, resources, and materials must be kept within this approved amount; overspending would make the project exceed its budget.

*(Other valid constraints from the same scenario: **Scope** — the four required modules must all be delivered; **Resource** — only six developers are available; **Quality/objective** — the system must raise sales by RM50,000.)*

### (b) Complete: "the project can be considered a total failure if ________________"
> …it is never completed and implemented (e.g., abandoned before delivery), or it fails so badly that the business cannot use it to process orders / it does not achieve its core objective of increasing sales by RM50,000.

*(A "total failure" = the project delivers no usable value. "Partially successful" = delivered late/over budget but usable. "Truly successful" = on time, within budget, meets all objectives.)*

## Quick Checklist for Exams
- Always give the **constraint type** + **evidence from the scenario** + **why it restricts the PM**.
- The "triple constraint" answer is almost always **Time, Cost, Quality/Scope**.
- If the scenario gives a staff count, also mention **Resource** constraint.
