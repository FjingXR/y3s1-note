MODULE 15

What is a static route?

Static route = a route you type in yourself. The router does not learn it automatically. You (the admin) tell the router: "to reach this network, go this way."

Why use static routes?

Static routes are often used even when a dynamic routing protocol (like OSPF) is running. They are simple, predictable, and use no extra CPU or bandwidth for updates.

4 types of static routes (by purpose)

TypeWhat it does
Standard static routeRoute to one specific network
Default static routeRoute that matches any destination not in the table
Floating static routeBackup route, only used if primary route fails
Summary static routeOne route that represents many smaller networks

Quick check

Q1. True or False — a static route is learned automatically by the router.
False. A static route must be manually typed in by the network administrator.
Topic 15.1

Static routes — the 3 next-hop options

When you type a static route, you must tell the router how to reach the next router. There are 3 ways:

Next-hop static route

Only the next router's IP address is given. The router works out the exit interface itself.

R1(config)# ip route 172.16.1.0 255.255.255.0 172.16.2.2

Directly connected static route

Only the exit interface is given. Best only for point-to-point serial links.

R1(config)# ip route 172.16.1.0 255.255.255.0 s0/1/0

Fully specified static route

Both exit interface AND next-hop IP are given. Needed for multiaccess (Ethernet) links.

R1(config)# ip route 172.16.1.0 255.255.255.0 g0/0/1 172.16.2.2
Common mistake

Using only the exit interface (directly connected style) on an Ethernet interface. This can cause extra ARP work and inefficiency. Best practice on Ethernet: use next-hop IP, or fully specified.

Command syntax (memorize this)

# IPv4 Router(config)# ip route network-address subnet-mask {ip-address | exit-intf} [distance] # IPv6 Router(config)# ipv6 route ipv6-prefix/prefix-length {ipv6-address | exit-intf} [distance]
IPv6 special rule

If the next-hop is a link-local address (starts with fe80::), you MUST use fully specified route (exit interface + address). Link-local addresses are not in the IPv6 routing table, so the router needs the interface to know which link it's on.

Practice questions

Q1. Which static route type should you avoid on a multiaccess Ethernet network, and use only on point-to-point serial links?
Directly connected static route (using only the exit interface).
Q2. Write the command for a next-hop static route to 192.168.5.0/24 via next hop 10.0.0.1.
ip route 192.168.5.0 255.255.255.0 10.0.0.1

Topic 15.3

Default static routes

A default route matches every destination that is not already in the routing table. Think of it as "if you don't know where else to send it, send it here."

Real-world example

Your home router does not know every website's exact route. Instead, it has ONE default route pointing to your ISP. Any traffic not matching a local rule goes to the ISP. This is exactly what an edge router or stub router does.

Command syntax

# IPv4 — called a "quad-zero route" Router(config)# ip route 0.0.0.0 0.0.0.0 {ip-address | exit-intf} # IPv6 Router(config)# ipv6 route ::/0 {ipv6-address | exit-intf}

Example

R1(config)# ip route 0.0.0.0 0.0.0.0 172.16.2.2 R1(config)# ipv6 route ::/0 2001:db8:acad:2::2
Exam key point — the mask

0.0.0.0 mask = 0 bits must match = matches everything.
::/0 = same idea for IPv6, 0 prefix bits required.
This is why it's called the "Gateway of Last Resort" — used only when nothing more specific matches.

How to spot it in show ip route: look for an asterisk * next to the code S — that marks the candidate default route selected as Gateway of Last Resort.

Practice questions

Q1. What is the IPv4 default static route command syntax called informally?
A "quad-zero route" — because it uses 0.0.0.0 0.0.0.0.
Q2. In the routing table, how do you identify which static route is the default route?
It has an asterisk (*) next to the "S" code, and appears as "Gateway of Last Resort".
Topic 15.4

Floating static routes

A floating static route is a backup route. It only gets used if the main (primary) route goes down.

The trick: Administrative Distance (AD)

AD = how trustworthy a route source is. Lower AD = more preferred.

0
Connected route
1
Static route (default)
110
OSPF
120
RIP
Key idea

To make a static route "float" (act as backup), give it a higher AD number than the primary route. Then the router only uses it when the better (lower AD) route disappears.

Example: primary + floating default route

R1(config)# ip route 0.0.0.0 0.0.0.0 172.16.2.2 R1(config)# ip route 0.0.0.0 0.0.0.0 10.10.10.2 5 R1(config)# ipv6 route ::/0 2001:db8:acad:2::2 R1(config)# ipv6 route ::/0 2001:db8:feed:10::2 5

The last number (5) is the AD. Because default static route AD is normally 1, the route with AD 5 is less preferred — it only appears in the routing table if R2 (the primary path) fails.

What happens if R2 fails?

1
R2 shuts down (or its interfaces go down).
2
R1 generates syslog messages about the link going down.
3
R1's routing table automatically switches to the floating (backup) route.

Summary static route (bonus — route summarization)

Combines several small static routes into one route. Saves memory, CPU, and speeds up lookups.

2 conditions to summarize

1. Networks must be continuous (able to combine into one address block).
2. All routes must use the same exit interface or next-hop IP.

Worked example — summarize 192.168.1.0, 192.168.2.0, 192.168.3.0

1
Write network addresses in binary.
2
Find where all 3 addresses stop matching (from left to right) — that's the summary boundary.
3
Count matching bits = 22 → mask is /22 = 255.255.252.0
4
Copy the 22 matching bits, fill rest with 0 → network address = 192.168.0.0
5
Final command: ip route 192.168.0.0 255.255.252.0 s0/2/1

Practice questions

Q1. What is the default Administrative Distance for a static route?
1 (very trustworthy — more preferred than dynamic protocols like OSPF at 110).
Q2. To make a static route a floating backup route, should its AD number be higher or lower than the primary route?
Higher. A higher AD number = less preferred = only used as backup.
Q3. Summarize these networks: 10.1.0.0/24, 10.1.1.0/24 into one route.
Both share the first 23 bits → 10.1.0.0/23 (mask 255.255.254.0)
Topic 15.5

Static host routes

A host route points to one single device, not a whole network.

IP versionMask / prefixMeaning
IPv4255.255.255.255 (/32)Exactly one host
IPv6/128Exactly one host

3 ways a host route appears in the routing table

1
Automatically installed — Cisco IOS installs a "local host route" (marked L) whenever you configure an IP address on an interface.
2
Static host route — you manually configure it to reach one specific device (e.g. a server).
3
Learned automatically via other methods — covered in later courses.

Example: static host route to a server

Branch(config)# ip route 209.165.200.238 255.255.255.255 198.51.100.2 Branch(config)# ipv6 route 2001:db8:acad:2::238/128 2001:db8:acad:1::2
IPv6 link-local next hop rule

If using a link-local address as next hop, you MUST specify the interface type and number. This is because link-local addresses can repeat on many different links — the router needs to know exactly which interface to use.

Practice question

Q1. What subnet mask makes an IPv4 route a "host route"?
255.255.255.255 (/32) — matches only that exact one IP address.

Module 15 summary — IP static routing

  • 4 static route types: standard, default, floating, summary
  • 3 next-hop styles: next-hop, directly connected, fully specified
  • Command: ip route network mask {ip | exit-intf} [distance]
  • Default route = 0.0.0.0 0.0.0.0 (IPv4) or ::/0 (IPv6) — matches everything
  • Floating route = same destination, higher AD number, used as backup only
  • Host route = /32 (IPv4) or /128 (IPv6) — points to exactly one device
MODULE 16 Topic 16.1

How a router processes a packet with static routes

This is the step-by-step journey of one packet from PC1 to PC3, across R1 → R2 → R3.

Decision logic at every router

Match found

Router uses the static route to find next-hop IP or exit interface, then forwards the packet.

No specific match

Router uses the default static route (if one is configured).

No match at all

Router drops the packet and sends an ICMP "destination unreachable" message back to the source.

Full journey: PC1 → R1 → R2 → R3 → PC3

1
PC1 sends the packet to its default gateway (R1).
2
R1 receives it, decapsulates (removes frame header), checks routing table.
3
R1 finds a match, re-encapsulates into a new frame, forwards out S0/1/0 to R2.
4
R2 does the exact same process — decapsulate, check table, forward to R3.
5
R3 receives packet, and sees destination matches its directly connected interface (PC3's LAN).
6
R3 checks its ARP table for PC3's MAC address. If missing, R3 sends an ARP request.
7
PC3 replies with its MAC address via ARP reply.
8
R3 builds a new frame (dest MAC = PC3, source MAC = R3's interface) and sends it. PC3 receives the packet.
Key exam point

The IP address never changes hop to hop — only the Layer 2 frame (MAC addresses) changes at every router along the path. This is the core idea of "de-encapsulate, route, re-encapsulate."

Practice question

Q1. What does a router do if the destination IP does not match ANY entry in the routing table (and there is no default route)?
The router drops the packet and sends an ICMP message back to the source.
Topic 16.2

Troubleshoot static and default routes

Networks fail for many normal reasons — an interface goes down, an ISP link drops, links get overloaded, or (very common!) the admin typed a wrong config.

Troubleshooting toolkit

CommandWhat it tells you
pingTests Layer 3 connectivity. Extended ping gives more options.
tracerouteShows the hop-by-hop path to destination using ICMP.
show ip routeDisplays the full routing table — check for missing/wrong entries.
show ip interface briefShows interface status (up/down) and IP address.
show cdp neighborsShows directly connected Cisco devices — confirms Layer 1/2 works.

Worked troubleshooting case

Scenario: PC1 cannot reach PC3.

1
Extended ping from R1's G0/0/0 to PC3 → fails.
2
Ping from R1's S0/1/0 to R2 → success.
3
Ping from R1's S0/1/0 to R3 → success.
4
So R1 is fine. Problem must be at R2 → check show ip route on R2.
5
R2's route to 172.16.3.0/24 is wrong (points via 192.168.1.1 instead of correctly to R3's real path).
6
Remove the incorrect route, add the correct one: ip route 172.16.3.0 255.255.255.0 172.16.2.1
Troubleshooting method (exam-friendly)

Work outward hop by hop from the source. Ping each router along the path one at a time. The first router that fails to reach the next hop is where the problem is.

Practice questions

Q1. Which command shows directly connected Cisco devices and confirms Layer 1/2 connectivity?
show cdp neighbors
Q2. What is the general strategy for isolating a routing problem across multiple routers?
Test connectivity hop by hop (ping each router in sequence) — the first failure point tells you where the misconfiguration is.

Module 16 summary — troubleshooting

  • Router logic: match → forward | no match, default exists → use default | no match at all → drop + ICMP
  • IP address stays the same across hops; only Layer 2 frame (MAC) changes each hop
  • Last router uses ARP to find destination host's MAC address
  • Troubleshoot in order: ping → traceroute → show ip route → show ip interface brief → show cdp neighbors
  • Isolate the fault by testing hop by hop from source outward

One-paragraph recap

  • Static routes are manually configured paths. 4 types: standard, default, floating, summary.
  • 3 ways to specify next hop: next-hop IP, exit interface, or both (fully specified).
  • Default routes use all-zero mask and catch any unmatched traffic (Gateway of Last Resort).
  • Floating routes are backups — set with a higher Administrative Distance.
  • Host routes (/32 or /128) point to one exact device, not a network.
  • Packet forwarding: router de-encapsulates, checks table, re-encapsulates, forwards — MAC changes each hop, IP stays the same.
  • Troubleshooting = test hop by hop with ping/traceroute, then confirm with show ip route, show ip interface brief, show cdp neighbors.
