MODULE 1 — CONCEPTS

What is OSPF?

OSPF (Open Shortest Path First) is a link-state routing protocol. Unlike distance-vector protocols (like RIP) that only know what their neighbour tells them, OSPF routers know the full network map.

Why OSPF?

OSPF was built to replace RIP. It converges faster, scales to much larger networks, and uses cost (not hop count) to choose the best path.

Key terms

TermMeaning
LinkAn interface on a router, or the network segment connecting two routers
Link-StateInformation about that link: IP address, prefix length, cost, up/down status
AreaA group of routers sharing the same LSDB. Helps organise large networks
CostOSPF's metric. Lower cost = better path. Based on interface bandwidth

Single-Area vs Multiarea

Single-Area OSPF

All routers in one area (best practice: area 0). Simple, good for small networks. This is what Chapter 2 covers.

Multiarea OSPF

Network split into many areas, all connected to area 0 (backbone). Smaller routing tables, less CPU work, faster convergence. Used in large enterprise networks.

OSPFv2 vs OSPFv3

OSPFv2 = IPv4. OSPFv3 = IPv6 (same basic operation, different addresses). This chapter covers OSPFv2.

Quick check

Q1. What does OSPF stand for?
Open Shortest Path First.
Q2. Is OSPF a link-state or distance-vector protocol?
Link-state — every router knows the full network topology, not just what its neighbour says.

Section summary

  • OSPF = link-state protocol, knows the full network map
  • Uses cost (bandwidth-based) not hop count
  • Single-area = one area for all routers; multiarea = hierarchical
  • OSPFv2 = IPv4; OSPFv3 = IPv6
Concepts

The three OSPF databases

OSPF keeps three separate databases on every router. Each has its own table and command to view it.

DatabaseTable NameContentsCommand
Adjacency DBNeighbour TableList of neighbour routers with bidirectional communicationshow ip ospf neighbor
Link-State DB (LSDB)Topology TableInfo about all routers in the area. All routers in an area have the same LSDBshow ip ospf database
Forwarding DBRouting TableBest routes (output of the SPF calculation). Unique per routershow ip route

How they connect — the 5-step process

1
Establish Neighbour Adjacencies — routers discover each other via Hello packets
2
Exchange LSAs — routers share link-state advertisements (their local network info)
3
Build the LSDB — each router collects all LSAs into its topology database
4
Execute SPF Algorithm — Dijkstra's algorithm calculates the shortest path to each network
5
Choose the Best Route — the SPF tree populates the routing table
Dijkstra's SPF Algorithm

Each router puts itself at the root of a tree and calculates the shortest path to every node based on cumulative cost. The result goes into the forwarding database (routing table).

Practice questions

Q1. Which OSPF database is the same on every router in the same area?
The Link-State Database (LSDB) / Topology Table — all routers in an area have an identical LSDB.
Q2. What command shows the neighbour table?
show ip ospf neighbor

Section summary

  • 3 databases: Adjacency (neighbour table), LSDB (topology table), Forwarding (routing table)
  • 5-step process: discover neighbours → exchange LSAs → build LSDB → run SPF → choose best route
  • SPF = Dijkstra's algorithm, based on cumulative cost
Concepts

The five OSPF packet types

OSPF routers exchange five types of Link-State Packets (LSPs) to build and maintain the network.

TypePacketPurpose
1HelloDiscover neighbours, build adjacencies, elect DR/BDR
2DBD (Database Description)Check if databases are synchronised (summary of LSDB)
3LSR (Link-State Request)Request specific, more current link-state information
4LSU (Link-State Update)Send the requested link-state records (carries LSAs inside)
5LSAck (Link-State Acknowledgment)Confirm receipt of LSR or LSU
Important distinction

LSU and LSA are often used interchangeably, but an LSU packet is the container that carries LSA messages inside. Think: envelope (LSU) and letter (LSA).

Hello packet — the most important one

The Type 1 Hello packet does three things:

  • Discovers OSPF neighbours and establishes neighbour adjacencies
  • Advertises parameters that must match between neighbours (Hello timer, Dead timer, area ID, etc.)
  • Elects the Designated Router (DR) and Backup DR (BDR) on multiaccess networks like Ethernet

Hello packets are sent to multicast address 224.0.0.5 (All OSPF Routers).

Practice questions

Q1. Name the five OSPF packet types in order.
1-Hello, 2-DBD, 3-LSR, 4-LSU, 5-LSAck.
Q2. Which packet type is used to discover neighbours?
Hello (Type 1).
Q3. What multicast address do OSPF routers use for Hello packets?
224.0.0.5 (All OSPF Routers).

Section summary

  • 5 packet types: Hello, DBD, LSR, LSU, LSAck
  • Hello = neighbour discovery + DR/BDR election
  • LSU carries LSAs (envelope vs letter)
Concepts

The seven OSPF states

Two routers go through these 7 states to become fully connected neighbours.

1
Down — No Hello received yet. Router starts sending Hellos.
2
Init — Hello received from neighbour (router sees the neighbour's Router ID).
3
Two-Way — Bidirectional. Each router sees its own RID in the other's Hello. DR/BDR election happens here on multiaccess networks.
4
ExStart — Routers decide who sends DBD first (highest RID wins).
5
Exchange — DBD packets exchanged. Routers compare LSDBs.
6
Loading — LSRs and LSUs used to get missing/updated info.
7
Full — Databases fully synchronised. Neighbour adjacency complete!
Normal states to expect

After convergence, neighbour state should be FULL. The only exception is on multiaccess broadcast networks where two DROTHERs might show 2-WAY — this is normal because DROTHERs do not form FULL adjacency with each other.

Practice questions

Q1. In which OSPF state does DR/BDR election take place?
Two-Way state.
Q2. What happens in the Exchange state?
Routers exchange DBD packets to compare their LSDBs.
Q3. What does the Full state mean?
The link-state databases are fully synchronised and the adjacency is complete.

Section summary

  • Down → Init → Two-Way → ExStart → Exchange → Loading → Full
  • Two-Way = bidirectional + DR/BDR election
  • Full = synchronised. Normal operational state.
  • 2-WAY between two DROTHERs is normal on broadcast networks
Concepts

DR & BDR on multiaccess networks

On multiaccess networks (e.g. Ethernet with many routers on the same VLAN), if every router flooded LSAs to every other router, traffic would become chaotic. OSPF solves this by electing a Designated Router (DR) to manage LSA distribution.

Three roles

RoleJobMulticast address
DR (Designated Router)Collects LSAs from all routers, distributes them to all routersListens on 224.0.0.6
BDR (Backup DR)Backup if DR fails. Listens passivelyListens on 224.0.0.6
DROTHERNeither DR nor BDR. Sends LSAs only to DR/BDRSends to 224.0.0.6

How election works

1
Highest interface priority (0–255) becomes DR. Second highest = BDR.
2
If priority is equal, highest Router ID wins. Second highest RID = BDR.
3
Priority 0 = cannot be DR or BDR (configured intentionally).
4
Default priority on broadcast interfaces = 1.
5
Elections are not pre-emptive. Adding a new router later does NOT trigger a new election.

If the DR fails

1
BDR automatically promotes itself to DR.
2
A new BDR election happens — the DROTHER with highest priority or RID wins.

Point-to-point links — no DR needed

On a direct link between two routers, DR/BDR is unnecessary. But by default, Cisco Ethernet interfaces use the BROADCAST network type (which triggers DR election). To fix this:

R1(config-if)# ip ospf network point-to-point
Loopback interfaces

By default, loopback interfaces are advertised as /32 host routes. To advertise the full subnet instead, configure ip ospf network point-to-point on the loopback.

Practice questions

Q1. What multicast address does a DROTHER use to send packets to the DR?
224.0.0.6 (All Designated Routers).
Q2. What happens if the DR fails?
The BDR promotes itself to DR, and a new BDR election takes place.
Q3. Do point-to-point links need a DR?
No. Use ip ospf network point-to-point to disable DR election on the link.

Section summary

  • DR manages LSA flooding; BDR is backup; DROTHERs only talk to DR/BDR
  • Election: priority first, then Router ID. Not pre-emptive.
  • Point-to-point links do not need DR/BDR
MODULE 2 — CONFIGURATION

OSPFv2 configuration basics

Step 1 — Enable the OSPF process

R1(config)# router ospf 10

The process-id (1–65535) is locally significant — it only matters on this router.

Step 2 — Set the Router ID

Cisco picks the Router ID in this order:

  1. Manually configured via router-id command (highest priority)
  2. Highest IP on any loopback interface
  3. Highest IP on any active physical interface
R1(config-router)# router-id 1.1.1.1 R1# clear ip ospf process

Step 3 — Enable OSPF on interfaces

Method A: network command (in router config mode):

R1(config-router)# network 10.10.1.0 0.0.0.255 area 0 R1(config-router)# network 10.1.1.5 0.0.0.0 area 0
  • Wildcard mask = inverse of subnet mask (e.g. /24 → 0.0.0.255)
  • Quad-zero (0.0.0.0) = exactly one interface
  • All routers must use the same area ID (best practice: area 0)

Method B: ip ospf command (on each interface):

R1(config)# interface GigabitEthernet 0/0/0 R1(config-if)# ip ospf 10 area 0

Step 4 — Passive interfaces

By default, OSPF sends Hellos out every enabled interface. On LANs without OSPF neighbours, this wastes bandwidth and creates security risks.

R1(config-router)# passive-interface GigabitEthernet 0/0/1

The network is still advertised to other OSPF routers — Hellos just stop being sent out that interface.

3 problems passive interfaces solve

1. Wasted bandwidth on unnecessary Hellos
2. Wasted CPU on every LAN device that has to process and discard OSPF messages
3. Security risk — OSPF packets can be intercepted and forged

Practice questions

Q1. What is the command to enable OSPF process with ID 20?
router ospf 20
Q2. What are the two ways to enable OSPF on an interface?
1) network command in router config mode. 2) ip ospf process-id area area-id on the interface.
Q3. Does a passive interface still advertise its network in OSPF?
Yes. It stops sending Hellos but the network is still advertised in LSAs.

Section summary

  • Enable: router ospf process-id
  • Router ID: manual → loopback → physical interface IP
  • Enable OSPF on interfaces: network or ip ospf
  • Passive interface stops Hellos, still advertises the network
Configuration

OSPF cost metric

OSPF uses cost as its metric. Lower cost = better path. Cost is based on interface bandwidth.

The formula

Cost = reference-bandwidth / interface-bandwidth

Default reference bandwidth = 100,000,000 bps (100 Mbps).

InterfaceSpeedDefault cost
Fast Ethernet100 Mbps1
Gigabit Ethernet1,000 Mbps1
10 Gigabit Ethernet10,000 Mbps1
The problem

FastEthernet, Gigabit, and 10GE all have cost = 1 because OSPF rounds to integers (100/1000 = 0.1 → 1). OSPF cannot tell which is faster! You must change the reference bandwidth on all routers.

Fix: adjust reference bandwidth

R1(config-router)# auto-cost reference-bandwidth 10000

With ref = 10000 Mbps:

InterfaceCost
Fast Ethernet (100 Mbps)100
Gigabit Ethernet (1000 Mbps)10
10 Gigabit Ethernet (10000 Mbps)1
Must configure on ALL routers

The auto-cost reference-bandwidth command must be applied to every router in the OSPF domain. Otherwise, different routers calculate different costs for the same links.

Alternative: manually set cost

R1(config-if)# ip ospf cost 30

Cost accumulates along the path

The total cost to a destination = sum of all link costs along the path.

R1# show ip route | include 10.10.2.0 O 10.10.2.0/24 [110/11] via 10.1.1.6

The [110/11] means: AD = 110 (OSPF), metric (cost) = 11.

Practice questions

Q1. What is the default OSPF cost for a Gigabit Ethernet interface?
1 (100,000,000 / 1,000,000,000 = 0.1 → rounded to 1).
Q2. What command changes the reference bandwidth and what value should you use for 10 Gigabit Ethernet links?
auto-cost reference-bandwidth 10000 (10000 Mbps = 10 Gbps).
Q3. What command manually sets OSPF cost on an interface?
ip ospf cost value

Section summary

  • Cost = ref-bw / interface-bw. Lower cost = better path.
  • Default ref = 100 Mbps — adjust for modern networks
  • Use auto-cost reference-bandwidth on all routers
  • Or ip ospf cost on specific interfaces
  • Total path cost = sum of all link costs
Configuration

OSPF timers

TimerDefaultMeaning
Hello Interval10 secondsHow often the router sends Hello packets
Dead Interval40 secondsHow long to wait without a Hello before declaring neighbour dead (4 × Hello)
Must match!

If two neighbouring routers have different Hello or Dead intervals, they will not form an adjacency.

How to view timers

R1# show ip ospf interface g0/0/0 Timer intervals configured, Hello 10, Dead 40, Wait 40, Retransmit 5

How to change timers

R1(config-if)# ip ospf hello-interval 5 R1(config-if)# ip ospf dead-interval 20

IOS automatically sets Dead = 4 × Hello when you change Hello, but it's best practice to set both explicitly.

When to change timers

Only change timers when you need faster convergence (detecting failures sooner). The defaults are best practice for most networks. Faster timers = more traffic.

Practice questions

Q1. What are the default Hello and Dead intervals?
Hello = 10 seconds, Dead = 40 seconds.
Q2. What happens if two potential neighbours have different Hello intervals?
They will not form an OSPF adjacency.
Q3. Name two commands used to change OSPF timers.
ip ospf hello-interval seconds and ip ospf dead-interval seconds.

Section summary

  • Hello = 10s, Dead = 40s. Must match between neighbours.
  • Dead = 4 × Hello (default). Can be changed per interface.
  • View with show ip ospf interface
Configuration

Default route propagation

A router that connects your OSPF network to the internet (or another non-OSPF network) is called an ASBR (Autonomous System Boundary Router).

Configuration steps

1
Create a default static route on the ASBR:
R2(config)# ip route 0.0.0.0 0.0.0.0 loopback 1
2
Tell OSPF to share it with all other routers:
R2(config-router)# default-information originate

Verify on other routers

R1# show ip route | begin Gateway Gateway of last resort is 10.1.1.6 to network 0.0.0.0 O*E2 0.0.0.0/0 [110/1] via 10.1.1.6, 00:11:08, GigabitEthernet0/0/0
  • O = OSPF
  • * = candidate for default route (Gateway of Last Resort)
  • E2 = external route type 2

Practice questions

Q1. What is an ASBR?
A router between the OSPF domain and a non-OSPF network (e.g. the internet).
Q2. What command makes OSPF propagate a default route?
default-information originate (in router config mode).

Section summary

  • ASBR connects OSPF to non-OSPF networks
  • Steps: ip route 0.0.0.0 0.0.0.0 + default-information originate
  • Other routers see it as O*E2 in the routing table

Neighbour troubleshooting

Two routers may not form an OSPF adjacency if:

  • Subnet masks do not match
  • Hello / Dead timers do not match
  • OSPF network types do not match (e.g. BROADCAST vs POINT-TO-POINT)
  • Missing or incorrect network command
  • Interface is shut down or has the wrong IP
Example: show ip ospf neighbor output
R1# show ip ospf neighbor Neighbor ID Pri State Dead Time Address Interface 3.3.3.3 0 FULL/ - 00:00:35 10.1.1.13 Gi0/0/1 2.2.2.2 0 FULL/ - 00:00:31 10.1.1.6 Gi0/0/0

Pri = 0 means point-to-point. State = FULL means adjacency is working.

Q3. Give three reasons why OSPF neighbours might not form an adjacency.
