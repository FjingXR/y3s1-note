Chapter 3.3 — State Management, Navigation Principles & UI Patterns

This page covers ephemeral vs app state, the Provider pattern, the 5 navigation principles, and common UI patterns: tabs, drawers, dialogs, pickers, and snackbars. Made only from your lecture slides.

MODULE 3.3

What is State Management? EXAM: Q1a

Lecture 3.3, slide 1–5

State management means handling data that changes over time, and updating the screen (UI) when it changes.

Q1. What is "state" in Flutter?

Answer

State = everything that exists in memory while the app is running. This includes app assets, UI variables, animation state, textures, fonts, and more.

Q2. What are the 2 types of state? EXAM FORMAT

Answer

See table below — memorise this comparison for the exam.
🔄 Ephemeral State📦 App State
Also calledUI state, local stateShared state
Where it livesInside ONE single widgetShared across MANY parts of the app
LifespanShort — gone when widget is removedCan persist between user sessions
How to manageStatefulWidget + setState()Provider, Riverpod, BLoC

Q3. Give examples of each state type EXAM

🔄 Ephemeral State examples

  • Current page in a PageView
  • Current progress of an animation
  • Current selected tab in a BottomNavigationBar

📦 App State examples

  • User preferences
  • Login info
  • Notifications in a social app
  • Shopping cart in an e-commerce app
  • Read/unread state of articles in a news app
Quick trick to decide

Ask: "Does another screen/widget need this data too?" If YES → App State. If it's only for this one widget and nobody else cares → Ephemeral State.

More practice

Is "current selected tab in a BottomNavigationBar" ephemeral or app state?
Ephemeral state — it's local UI state, only matters to that one widget.
Is the "shopping cart" in an e-commerce app ephemeral or app state?
App state — the cart data is needed across many screens (product page, cart page, checkout page) and often needs to persist.
What widget/method is used to manage simple ephemeral state?
StatefulWidget, using setState().
App State Management

The Provider pattern EXAM

Lecture 3.3, slide 6–11

Provider is a simple way to share App State across many widgets, without passing data manually through every widget.

Q1. What class does Provider use to notify changes?

Answer

ChangeNotifier — a class you extend to hold your data. When data changes, call notifyListeners() to tell all listening widgets to rebuild.

class CounterProvider extends ChangeNotifier { int _counter = 0; int get counter => _counter; void increment() { _counter++; notifyListeners(); // tells listeners: rebuild now } }

Q2. What are the 4 steps to set up Provider? EXAM FORMAT

1
Create a class that extends ChangeNotifier — holds your data + methods that change it.
2
Wrap your app (or part of it) in ChangeNotifierProvider, in main() — this creates and provides the object.
3
Use Consumer widget in your UI to read the value and rebuild automatically when it changes.
4
Use context.read<T>() to call a method (like increment()) — this does NOT rebuild the widget, just runs the action.
void main() { runApp( ChangeNotifierProvider( create: (context) => CounterProvider(), child: someWidget, ), ); }
// multiple providers at once MultiProvider( providers: [ ChangeNotifierProvider(create: (context) => Provider1()), ChangeNotifierProvider(create: (context) => Provider2()), ], child: someWidget, )
body: Center( child: Consumer( builder: (context, counter, child) { return Text('${counter.counter}'); }, ), ), floatingActionButton: FloatingActionButton( onPressed: () { context.read().increment(); }, child: const Icon(Icons.add), ),

Q3. Consumer vs context.read() — what's the difference? EXAM

Consumercontext.read()
PurposeREAD value and auto-rebuild UI when it changesCALL a method/action, without rebuilding
Used inbuild() method, to show dataButton onPressed, to trigger a change
Where to find it

Chapter_3_Merged.pdf — State Management - Provider slides (Chapter 3.3, slides 6 to 11).

More practice

What method must you call inside ChangeNotifier to update the UI?
notifyListeners() — tells all Consumer widgets listening to this provider to rebuild.
What widget lets you provide more than one ChangeNotifier at once?
MultiProvider — takes a list of providers.
Should you use Consumer or context.read() inside a button's onPressed?
context.read() — you just want to trigger an action, not rebuild that part of the UI.

The 5 Navigation Principles EXAM: Q1a

Lecture 3.3, slide 16–23

These 5 rules describe how navigation should behave in every Flutter app. This is a common exam topic — memorise the exact wording.

Q1. List all 5 navigation principles EXAM FORMAT

Answer

See numbered list below.
1
Fixed start destination — every app has one fixed starting screen. This is also the last screen the user sees before returning to the home launcher.
2
Navigation state is a stack of destinations — the top of the stack is the current screen; earlier screens below it are your navigation history.
3
Up and Back are identical within your app's task — inside your own app, the Up button (top of app bar) behaves exactly like the phone's Back button.
4
The Up button never exits your app — if the user is on the start destination, the Up button does not appear at all.
5
Deep linking simulates manual navigation — jumping straight to a detail screen (deep link) should still build the same back-stack as if the user tapped through manually.

Pressing Back pops the top block off — you go back down the stack, one screen at a time.

Q3. Why does the Up button disappear at the start destination? EXAM

Answer

Because Up must NEVER exit the app. At the start destination, there is no "up" screen inside the app to go to — going further up would mean leaving the app, which breaks Principle 4.

Q4. What does "deep linking simulates manual navigation" mean?

Answer

A deep link (e.g. tapping a notification that opens a detail screen directly) should still build a normal-looking back stack — as if the user had tapped through the app's main screen first, then to the detail screen. This keeps Back/Up behavior consistent no matter how the user arrived.

Exam tip

A common exam question gives a screen scenario (e.g. "user is on screen C, taps Back twice") and asks which screen they land on. Use the stack diagram: popping removes the top block each time.

Where to find it

Chapter_3_Merged.pdf — Navigation principles slides (Chapter 3.3, slides 16 to 23).

More practice

User is on stack [Start, A, B, C] and presses Back once. Which screen do they see?
Screen B — the top of the stack (C) is popped off, revealing B underneath.
Are Up and Back always identical in Flutter?
Only WITHIN your app's own task/stack — not necessarily true across different apps or tasks.
Which principle explains why the Up button is missing on your app's home screen?
Principle 4 — The Up button never exits your app, so it's hidden at the start destination.
UI Pattern

Tab Navigation

Lecture 3.3, Tab section

Tabs let users switch between different views inside one screen, using a TabBar at the top or bottom.

Q1. What 3 pieces make up Flutter's tab system?

TabBar

Displays the row of tabs (icons/labels) the user taps.

TabBarView

Displays the content that matches the selected tab.

TabController

Manages which tab is active and handles switching between them.

Q2. Fixed Tabs vs Scrollable Tabs — what's the difference?

Answer

  • Fixed Tabs — all tabs fit on screen at once, evenly spaced. Good for few tabs (2–4).
  • Scrollable Tabs — tabs can be swiped left/right if there are too many to fit. Good for many tabs.

Q3. Show the 3-step setup for tabs EXAM

1
Wrap Scaffold in DefaultTabController, set length (number of tabs).
2
Add a TabBar inside AppBar's bottom property, listing each Tab().
3
Add a TabBarView as the body, with matching content widgets in the same order as the tabs.
return MaterialApp( home: DefaultTabController( length: 3, child: Scaffold( appBar: AppBar( bottom: const TabBar( tabs: [ Tab(icon: Icon(Icons.directions_car)), Tab(icon: Icon(Icons.directions_transit)), Tab(icon: Icon(Icons.directions_bike)), ], ), ), body: const TabBarView( children: [ Icon(Icons.directions_car), Icon(Icons.directions_transit), Icon(Icons.directions_bike), ], ), ), ), );
Order matters

The Nth tab in TabBar always shows the Nth widget in TabBarView. Keep both lists in matching order.

Where to find it

Chapter_3_Merged.pdf — Tab section (Chapter 3.3).

More practice

What widget manages which tab is currently selected?
TabController (often supplied automatically by DefaultTabController).
Which tab style would you use for 8 category tabs that don't fit on one screen?
Scrollable Tabs — lets the user swipe to see tabs that don't fit.

Drawer Navigation EXAM

Lecture 3.3, Drawer section

A Drawer is a side menu that slides in from the edge of the screen — good for apps with many navigation destinations.

Q1. When should you use a Navigation Drawer? EXAM

Answer

Recommended when you have:

  • 5 or more top-level destinations
  • 2 or more levels of navigation hierarchy
  • Need for quick navigation between unrelated destinations

Q2. What are the 5 steps to build a Drawer? EXAM FORMAT

1
Create a Scaffold.
2
Add a drawer property to the Scaffold.
3
Populate the drawer with a ListView of items (e.g. DrawerHeader + ListTiles).
4
Open the drawer programmatically with Scaffold.of(context).openDrawer().
5
Close the drawer programmatically with Navigator.pop(context).
Drawer( child: ListView( padding: EdgeInsets.zero, // remove default padding children: [ const DrawerHeader( decoration: BoxDecoration(color: Colors.blue), child: Text('Drawer Header'), ), ListTile(title: const Text('Item 1'), onTap: () { ... }), ListTile(title: const Text('Item 2'), onTap: () { ... }), ], ), )
// opening the drawer via hamburger icon leading: Builder( builder: (context) { return IconButton( icon: const Icon(Icons.menu), onPressed: () { Scaffold.of(context).openDrawer(); }, ); }, )
Remove default ListView padding

Always set padding: EdgeInsets.zero on the drawer's ListView — otherwise there's a strange visible gap at the top.

Where to find it

Chapter_3_Merged.pdf — Drawer section (Chapter 3.3).

More practice

How many top-level destinations should you have before considering a Drawer instead of tabs?
5 or more top-level destinations.
What method closes the drawer after tapping a menu item?
Navigator.pop(context).

Dialogs — AlertDialog vs SimpleDialog EXAM

Lecture 3.3, Dialog section

Dialogs are popup boxes that interrupt the user to show something important or ask them to choose.

Q1. AlertDialog vs SimpleDialog — what's the difference? EXAM FORMAT

Answer

See table below.
FeatureAlertDialogSimpleDialog
PurposeInform user of a situation that needs acknowledgmentOffer user a choice between several options
ContentOptional title + content text + action buttonsOptional title + list of choice options
Use case"Delete this file?" confirmation, error message"Choose your department" selection menu

AlertDialog

showDialog( context: context, barrierDismissible: false, // must tap button! builder: (context) { return AlertDialog( title: const Text('AlertDialog Title'), content: const Text('Approve this message?'), actions: [ TextButton( child: const Text('Approve'), onPressed: () { Navigator.of(context).pop(); }, ), ], ); }, );

SimpleDialog

showDialog( context: context, builder: (context) { return SimpleDialog( title: const Text('Select assignment'), children: [ SimpleDialogOption( onPressed: () { Navigator.pop(context, Department.treasury); }, child: const Text('Treasury'), ), ], ); }, );

Q2. What does barrierDismissible: false mean?

Answer

The user CANNOT close the dialog by tapping outside it — they must tap one of the dialog's buttons. Used when the user must make a real decision (e.g. confirm delete).

Where to find it

Chapter_3_Merged.pdf — Dialog section (AlertDialog, SimpleDialog) — Chapter 3.3.

More practice

Which dialog type would you use to let a user pick their preferred language from a list?
SimpleDialog — it offers a choice between multiple options.
Which dialog type would you use to warn "Are you sure you want to log out?"
AlertDialog — informs the user and asks for acknowledgment via action buttons (e.g. Yes/Cancel).

Date and Time Pickers

Lecture 3.3, Picker section

Pickers let users choose a date or time using a built-in, correctly-formatted UI.

Q1. What are the 2 built-in picker functions?

Answer

showDatePicker and showTimePicker — both are async functions that return the value the user picked.

Q2. Why use these instead of a plain text field?

Answer

They make sure the user picks a value that is valid, correctly formatted, and adjusted to the user's locale (region settings) automatically.

DateTime _selectedDate = DateTime.now(); Future _selectDate(BuildContext context) async { final DateTime? picked = await showDatePicker( context: context, initialDate: _selectedDate, firstDate: DateTime(2000), lastDate: DateTime(2100), ); if (picked != null) { setState(() { _selectedDate = picked; }); } }

Q3. What do initialDate, firstDate, and lastDate control?

PropertyMeaning
initialDateThe date shown/selected when the picker first opens
firstDateThe earliest date the user is allowed to pick
lastDateThe latest date the user is allowed to pick
Where to find it

Chapter_3_Merged.pdf — Date and Time Pickers section (Chapter 3.3).

More practice

What type of function is showDatePicker — sync or async?
Async — you must "await" its result since it waits for the user's input.
What happens if the user cancels the date picker (taps outside)?
"picked" will be null — code should check "if (picked != null)" before using the value.

Snackbar EXAM: Q1a

Lecture 3.3, Snackbar section

A Snackbar is a small message that pops up briefly at the bottom of the screen, to inform the user something happened.

Q1. How do you show a Snackbar?

Answer

Use ScaffoldMessenger.of(context).showSnackBar(snackBar) — it finds the ScaffoldMessenger in the widget tree and displays the SnackBar.

final snackBar = SnackBar( content: const Text('Yay! A SnackBar!'), action: SnackBarAction( label: 'Undo', onPressed: () { // code to undo the change }, ), ); ScaffoldMessenger.of(context).showSnackBar(snackBar);

Q2. Snackbar vs Dialog — what's the difference? EXAM FORMAT

Answer

See table below — a very common exam comparison.
AspectSnackbarDialog
PriorityLowHigh
User actionOptional — can ignore itRequired — user must respond
DismissalDisappears automatically after a few secondsBlocks app usage until user takes an action or exits
Use case"Message deleted" + Undo option"Delete this file?" confirmation, form errors
Exam tip

Snackbar = low-priority, non-blocking, "FYI" message. Dialog = high-priority, blocking, needs a decision. Pick based on how important/urgent the message is.

Where to find it

Chapter_3_Merged.pdf — Snackbar section (Chapter 3.3).

More practice

Which widget finds and shows the SnackBar in the widget tree?
ScaffoldMessenger.
Would you use a Snackbar or Dialog to confirm "Delete this file permanently?"
Dialog (AlertDialog) — this is a high-priority action needing a required user decision, not something to auto-dismiss.
What optional feature does a Snackbar commonly have?
A SnackBarAction (e.g. an "Undo" button) to reverse the last action.

Chapter 3.3 — full cheat sheet

  • State = everything in memory while app runs. 2 types: Ephemeral (local, single widget) vs App State (shared, persists).
  • Ephemeral examples: current page, animation progress, selected tab. App State examples: login info, cart, preferences.
  • Provider setup: ChangeNotifier class → ChangeNotifierProvider in main() → Consumer to read → context.read() to call actions.
  • 5 Navigation Principles: (1) Fixed start destination, (2) Stack of destinations, (3) Up = Back within task, (4) Up never exits app, (5) Deep linking simulates manual nav.
  • Tab setup: DefaultTabController(length) → TabBar (tabs) → TabBarView (matching content).
  • Drawer setup (5 steps): Scaffold → add drawer → populate ListView → openDrawer() → Navigator.pop() to close. Use when ≥5 destinations or ≥2 nav levels.
  • AlertDialog = inform + acknowledge. SimpleDialog = offer a choice.
  • Date/Time Pickers: showDatePicker/showTimePicker — ensures valid, correctly formatted, locale-adjusted values.
  • Snackbar (low priority, optional, auto-dismiss) vs Dialog (high priority, required, blocks app).
