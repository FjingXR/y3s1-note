Chapter 3.1 — Widgets, Layout & Performance

This page covers Flutter widgets (basic UI pieces), how layout works (single-child vs multi-child), design systems (Material vs Cupertino), sliver widgets for scrolling, and performance tips. Made only from your lecture slides.

MODULE 3.1

What are widgets? EXAM: Basics

Lecture 3.1, slide 4–27

A widget is one piece of the UI (user interface = what the user sees and touches). Everything in Flutter is a widget — even layout and spacing.

Q1. What is a widget in Flutter?

Answer

A widget defines 3 things:

  • Appearance — how it looks
  • Layout — where it sits and how big it is
  • Behavior — what it does (e.g. button press)

Widgets are nested — one widget can hold other widgets inside it. This forms a tree shape.

Column ├── Container │ └── Column │ ├── Text │ ├── Search Bar │ └── Column │ ├── Row │ │ └── Row │ │ └── Text │ ├── Wrap │ ├── ListView │ └── Card

Q2. What makes widgets useful (2 characteristics)?

Answer

  • Customizable — most widgets have properties you can change (color, size, text) to fit your own design.
  • Reusable — you build a widget once, then use it many times in your app. Saves code.
// reusable custom button example CustomButton( text: 'Custom Button', onPressed: () { /* handle press */ }, color: Colors.green, )

Q4. Text vs Text.rich — what's the difference?

Answer

Both show text, but Text.rich lets you style different parts of the same sentence differently (e.g. bold one word only).

Text

One string, one single style for the whole text.

Text( 'Hello, world!', textDirection: TextDirection.ltr, )

Text.rich

Combine many TextSpan — each part can have its own style.

Text.rich( TextSpan( text: 'Hello', children: [ TextSpan(text: ' beautiful ', style: TextStyle(fontStyle: FontStyle.italic)), TextSpan(text: 'world', style: TextStyle(fontWeight: FontWeight.bold)), ], ), )

overflow: TextOverflow.ellipsis — if text is too long for the box, it cuts and shows "…" at the end.

Q5. What are the 3 ways to read a value from TextField? EXAM

Answer

You can get what the user typed using: onChanged(), onSubmitted(), or a Controller.

onChanged()

Runs every time the user types a new character. This is the default way to read value.

onSubmitted()

Runs only when user finishes editing (e.g. presses Enter/Done). Good for moving focus to next field.

TextEditingController

An object linked to the field. Can: set initial text, get current text, listen to changes, clear text.

TextField( decoration: InputDecoration( labelText: 'Email Address', hintText: 'Enter your email', icon: Icon(Icons.email), ), keyboardType: TextInputType.emailAddress, controller: _emailController, onChanged: (text) => print('Email: $text'), )
Controller cleanup

Always call _textController.dispose() inside the widget's dispose() method. This prevents memory leaks (unused memory that never gets freed).

Q6. What is InputDecoration used for?

Answer

It decorates a TextField with: label, icon, inline hint text, and error text. Set decoration: null to remove all decoration.

Q9. Row vs Column — what's the difference?

Answer

  • Row — arranges children horizontally (left to right)
  • Column — arranges children vertically (top to bottom)

Expanded makes a child take up all leftover space.

Q10. What does Scaffold provide?

Answer

Scaffold gives the basic Material Design screen structure. It provides ready-made APIs for drawers, snack bars, and bottom sheets.

Widget Types

StatelessWidget vs StatefulWidget EXAM: Q1a

Lecture 3.1, slide 47–52

Every widget in Flutter is either Stateless (never changes) or Stateful (can change over time).

Q1. What is the difference between StatelessWidget and StatefulWidget? EXAM FORMAT

Answer

See table below — memorise this for the exam.
StatelessWidgetStatefulWidget
AppearanceFixed — never changesCan change (reacts to user input / data)
Internal stateDoes NOT hold stateHolds its own state, managed by a State object
Rebuild triggerOnly rebuilds if parent rebuilds itRebuilds itself when setState() is called
Example useStatic text, icon, logoCheckbox, form input, counter, animation

StatelessWidget example

class GreenFrog extends StatelessWidget { const GreenFrog({ super.key }); @override Widget build(BuildContext context) { return Container( color: const Color(0xFF2DBD3A)); } }

StatefulWidget example

class YellowBird extends StatefulWidget { const YellowBird({ super.key }); @override State createState() => _YellowBirdState(); } class _YellowBirdState extends State { @override Widget build(BuildContext context) { return Container( color: const Color(0xFFFFE306)); } }

Q2. How does setState() work?

Answer

Calling setState() tells Flutter: "data changed, please rebuild this widget's UI". Flutter then re-runs build() to draw the new look.

class _BirdState extends State { double _size = 1.0; void grow() { setState(() { _size += 0.1; }); // triggers rebuild } @override Widget build(BuildContext context) { return Container( color: widget.color, transform: Matrix4.diagonal3Values(_size, _size, 1.0), child: widget.child, ); } }
Exam tip

If asked "which widget type would you use for a login form?" → StatefulWidget, because the text field values and button states change based on user input.

Where to find it

Chapter_3_Merged.pdf — slides 47 to 52 (Stateless vs Stateful Widget).

More practice

A logo that never changes — Stateless or Stateful?
StatelessWidget — fixed appearance, no interaction needed.
What object manages a StatefulWidget's state?
A State object, created by createState().
What happens if you change a variable WITHOUT calling setState()?
The variable changes in memory, but the UI does NOT update — Flutter doesn't know to rebuild. The screen stays out of sync with the data.

Layout System

Single-child vs multi-child layout EXAM: Q1a

Lecture 3.1, slide 59–85

A layout widget arranges other widgets. Flutter splits layout widgets into 2 groups, based on how many children they can hold.

Q1. What is the difference between single-child and multi-child layout widgets? EXAM FORMAT

Answer

See table below.
Single-childMulti-child
MeaningCan only hold ONE child widgetCan hold MANY children
ExamplesAlign, AspectRatio, Center, ConstrainedBox, Container, Padding, SizedBoxRow, Column, GridView, ListView, Stack, Wrap

Q2. Single-child widgets — what does each do?

Align

Positions its child inside itself (e.g. top-right corner).

AspectRatio

Forces child to a specific width:height ratio (e.g. 16:9).

Center

Centers its child inside itself.

Container

Groups a widget and adds styling — padding, margin, border, color.

Padding

Adds empty space around its child.

SizedBox

Forces a specific fixed width and height.

Container( width: 200.0, height: 100.0, color: Colors.blue, padding: EdgeInsets.all(20.0), alignment: Alignment.center, child: Text("Hello World!"), )

Q4. What are the 4 key features of multi-child layout widgets?

Answer

  • Layout management — handles arranging/positioning children
  • Alignment — control with mainAxisAlignment (Row/Column) or alignment (Stack)
  • Spacing — control gap between children with spacing property (Flutter 3.27+)
  • Sizing — control child size with mainAxisSize or flex

Utility Widgets

Other useful widgets

Lecture 3.1, slide 84–85

Beyond basic widgets and layouts, Flutter provides utility widgets for async data, gestures, animations, and flex-based sizing.

Q1. What are FutureBuilder and StreamBuilder?

FutureBuilder

Builds a widget based on the result of an async computation (a Future). Shows a loading state while waiting, then the result when done.

StreamBuilder

Builds a widget based on the latest data from a stream. Rebuilds every time the stream emits a new value — good for real-time data.

FutureBuilder<String>( future: fetchData(), // async Future builder: (context, snapshot) { if (snapshot.connectionState == ConnectionState.done) return Text(snapshot.data!); return CircularProgressIndicator(); }, )

Q2. What is GestureDetector used for?

Answer

GestureDetector detects gestures (tap, double-tap, long press, swipe, drag) on its child widget. Wrap any widget with it to make it respond to user input — even if that widget has no built-in tap handler.

GestureDetector( onTap: () => print('Tapped!'), onLongPress: () => print('Long pressed!'), child: Container( color: Colors.blue, child: Text('Tap me'), ), )

Q3. What is the Hero widget?

Answer

Hero creates a smooth animated transition between two screens. The same widget (e.g. an image) flies from its position on the first screen to its position on the second screen during navigation. Use matching hero tags on both screens.

Q4. What does the Flex widget do?

Answer

Flex provides more control over child layout using flex factors. Row and Column are actually built on top of Flex — Row = Flex with direction horizontal, Column = Flex with direction vertical. You can use Flex directly when you need to switch direction dynamically.

Where to find it

Chapter_3_Merged.pdf — slides 84 to 85 (Layout Widgets: Flex, Wrap; Other Widgets: FutureBuilder, StreamBuilder, GestureDetector, Hero).

Quick recap

  • FutureBuilder — builds UI from a Future (one async result).
  • StreamBuilder — builds UI from a Stream (multiple values over time).
  • GestureDetector — wraps any widget to detect taps, swipes, long presses.
  • Hero — animated flight between two screens during navigation.
  • Flex — parent of Row/Column; controls direction and flex factors.
Advanced Scrolling

Sliver widgets

Lecture 3.1, slide 86–92

Sliver widgets are special building blocks for scrollable areas. They give more control than a normal ListView.

Q1. What is a Sliver widget?

Answer

Slivers are widgets made specifically for scroll areas. Unlike a normal box widget, a sliver can change its own size/shape based on scroll position — this makes effects like expanding headers possible.

Q2. Why use slivers instead of a normal ListView? (3 benefits)

Answer

  • Customization — fine control over scroll behavior and look
  • Performance — more efficient than standard scroll widgets for big data (only loads what's visible)
  • Flexibility — combine different slivers for unique scroll effects
Key exam idea

A normal ListView loads ALL records into memory. SliverList only loads records that are visible to the user right now. This saves memory — important because mobile devices have limited RAM.

Q3. List 5 common Sliver widgets and their purpose EXAM

WidgetPurposeUse Case
SliverAppBarApp bar that can expand/collapse while scrollingBig header image that shrinks as user scrolls down
SliverListRenders a vertical list, like ListView, but more flexibleLong list of chat messages or news feed
SliverGridRenders a grid, like GridView, inside a scroll areaPhoto gallery grid
SliverToBoxAdapterPuts a normal box widget (Text/Container) inside a scroll areaAdding a plain banner or title inside a CustomScrollView
SliverFixedExtentListLike SliverList but forces same height for all childrenUniform-height list items — faster rendering

Q4. How do you use sliver widgets together?

Answer

Slivers are used inside CustomScrollView. Its slivers property takes a list of sliver widgets, letting you combine them for your desired scroll layout.

Best Practices

Performance best practices EXAM: Q1a

Lecture 3.1, slide 94–100

Mobile devices are weaker than desktop PCs (limited CPU, RAM, battery). These 5 practices help your Flutter app run fast and smooth.

Q1. What are the 5 performance best practices?

Answer

See numbered list below — memorise all 5 for the exam.
1
Minimize widget rebuilds — avoid heavy/slow work inside build(), since it can run often. Use const for widgets that never change — Flutter skips rebuilding them.
2
Optimize layout — avoid unnecessary nesting (too many widgets inside widgets); keep the widget tree flat to reduce render time. Use LayoutBuilder for layouts that depend on available space.
3
Efficient image loading — use Image.network with caching for network images; resize images to the size actually needed; use efficient formats like WebP instead of JPEG/PNG/GIF.
4
State management — call setState() only when truly needed. For complex apps, use Provider, Riverpod, or BLoC (Business Logic Component) instead of many scattered setState calls.
5
Use Flutter's built-in widgets — Flutter's own widgets are already optimized. Prefer them over building custom versions from scratch.

Q2. Why does using const help performance?

Answer

const tells Flutter the widget's properties will NEVER change. Flutter can then skip rebuilding it when the parent rebuilds — saving CPU work.

Q3. Why is WebP recommended for images? EXAM

Answer

WebP is a raster (pixel-based) image format designed to replace JPEG, PNG, and GIF. It gives smaller file size for similar quality — meaning faster load and less data/storage used. This matters because mobile devices have limited storage, RAM, and slower/unreliable network.

Link back to Chapter 1

These 5 practices exist BECAUSE mobile devices have limits: weak CPU, small RAM, unreliable network, battery drain, small screen (from Chapter 1.1). Performance code = working around these limits.
