Question 1(a)(ii)

Lecture 1.1, slide 19-20 — "Types of Mobile Apps"

Q: Select the most appropriate mobile app type (native, hybrid or mobile web) for a highly interactive 3D mobile game. Briefly justify your selection. (2 marks)

  • Answer: Native
  • 3D games need maximum performance (GPU, CPU, memory)
  • Native gives wide access to device features (sensors, haptics, GPU)
  • Fast performance is critical for real-time 3D rendering
  • Hybrid and mobile web depend on network speed — too slow for interactive games

Practice

Question 1 — Practice Questions

Try These

P1. Which app type has the lowest development cost but the worst device access?
Mobile web — low cost, very limited access to device features, no app store distribution.
P2. What is the difference between the "Paused" and "Detached" states in Flutter?
Paused = app is in background but still in memory. Detached = app is no longer attached to any view and is fully detached.
P3. Why would a shopping mall app use hybrid instead of native?
Lower cost (single codebase), good enough performance for a non-game app, still available on app stores.

Question 1 — Key Takeaways

  • Three app types: Native (best perf, high cost, multiple codebases), Hybrid (balance, single codebase, app stores), Mobile Web (cheapest, no app stores, very limited device access).
  • Native is best for performance-critical apps like 3D games.
  • Flutter app lifecycle has 4 states: Resumed, Inactive, Paused, Detached.
  • Resumed = active/visible; Inactive = brief transition; Paused = background; Detached = fully removed.

Question 2(a)

Lecture 3.1 — "StatelessWidget vs StatefulWidget"

Q: Provide TWO (2) differences between stateless and stateful widgets. (4 marks)

Side-by-side comparison

StatelessWidget

  • Immutable — once built, cannot change
  • No setState() method
  • Does not rebuild when data changes
  • Best for static UI (labels, icons, logos)

StatefulWidget

  • Mutable — has a State object that can change
  • Uses setState() to trigger rebuild
  • Rebuilds UI when state changes
  • Best for interactive UI (forms, buttons, animations)
DifferenceStatelessWidgetStatefulWidget
MutabilityImmutableMutable (State object can change)
UI UpdateNo setState(), no rebuildUses setState() to rebuild UI

MODULE 3.2

Question 2(c)

Lecture 3.2 — "Internationalization" / .arb files / flutter_localizations

Q: Present any TWO (2) methods of internationalising mobile apps for adapting to different languages, cultures and regions. Briefly elaborate your answers. (4 marks)

  • 1. Locale-based resource files (.arb files)
    • Store translated strings in separate .arb files (one per language)
    • Flutter loads the correct file based on device locale
    • Example: app_en.arb, app_ms.arb, app_zh.arb
  • 2. Flutter's Localizations widgets
    • Use MaterialApp's localizationsDelegates and supportedLocales
    • Provides locale-specific content for different languages and regions
    • Works with flutter_localizations package

Question 2(e)

Lecture 3.3, slide 17 — "Navigation Principles"

Q: Identify the FIVE (5) navigation principles (explanation is not required). (5 marks)

1 Fixed start destination — every app has a fixed start destination (the last screen seen when returning to launcher)
2 Navigation state is represented as a stack of destinations — top of stack = current screen, previous destinations = history
3 Up and Back are identical within your app's task — Up button (app bar) and Back button behave the same inside the app
4 The Up button never exits your app — at the start destination, Up button does not appear
5 Deep linking simulates manual navigation — opening a link should behave like manually navigating to that screen

Source: Chapter 3.3 lecture slides 17-23 — "Navigation Principles" section.

Practice

Question 2 — Practice Questions

Try These

P1. Which widget type should you use for a label that never changes? Why?
StatelessWidget — it is immutable and does not need setState(). The label never changes, so there's no need for a mutable State object.
P2. What is the "stack" in Flutter navigation? Give an example.
A stack is the navigation history. When you push Screen2 on top of Screen1, the stack is [Screen1, Screen2]. When you pop Screen2, you go back to Screen1.
P3. You are building a to-do list app. The current selected tab is ephemeral state. What would be an example of app state in this app?
The list of to-do items and user login info are app state — they need to be shared across screens and persist between sessions.
P4. Why is using WebP better than PNG for mobile apps?
WebP files are smaller than PNG for the same quality, which reduces download time and storage usage on mobile devices.

Question 2 — Key Takeaways

  • StatelessWidget = immutable, no setState(), for static UI. StatefulWidget = mutable, uses setState(), for interactive UI.
  • Image performance: use Image.network with caching, resize images, use WebP format.
  • Internationalization: .arb resource files (one per language) + Flutter's Localizations widgets (localizationsDelegates, supportedLocales).
  • Ephemeral state = local, single widget, not shared. App state = shared across app, persists between sessions.
  • 5 navigation principles: fixed start, stack-based, Up=Back, Up never exits, deep linking simulates manual navigation.
