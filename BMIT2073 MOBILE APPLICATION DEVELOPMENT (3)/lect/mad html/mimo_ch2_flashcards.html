Deep Dive Flashcards

Click any card to flip. Master the 4 AppLifecycleStates and their transitions.

Resumed
What is the Resumed state?
click to reveal
answer
The app is fully visible and interactive. It is in the foreground and receiving user input. This is the normal running state — the user can tap, scroll, type, etc.
Resumed
What action should you take when entering Resumed?
click to reveal
answer
• Resume animations — start playing video, restart timers
• Refresh data — fetch latest content from server
• Re-enable input — accept taps, gestures, keyboard
• Restart audio — resume music playback
Inactive
What is the Inactive state?
click to reveal
answer
A temporary transition state. The app is still partially visible but not receiving input. It happens between Resumed and Paused — e.g. when the app is animating to the background or a system dialog appears.
Inactive
What action should you take when entering Inactive?
click to reveal
answer
• Pause animations — stop non-essential movement
• Pause game — freeze game state if it's a game
• Reduce CPU usage — stop unnecessary processing
• Do NOT save critical data yet — the app may return to Resumed
Paused
What is the Paused state?
click to reveal
answer
The app is in the background and not visible. It may still be partially visible on some Android devices (e.g. split-screen). On iOS it is fully hidden. The app is not receiving user input.
Paused
What action should you take when entering Paused?
click to reveal
answer
• Save user progress — persist data to disk
• Pause audio/video — stop media playback
• Stop GPS tracking — conserve battery
• Release camera/microphone — free up hardware
• Reduce network calls — no point fetching data user can't see
Detached
What is the Detached state?
click to reveal
answer
The app is fully destroyed — all resources are released. The engine is detached from the platform. This happens when the system kills the app or the user swipes it away from recents. The app must be recreated from scratch to run again.
Detached
What action should you take when entering Detached?
click to reveal
answer
• Clean up all resources — close streams, dispose controllers
• Save critical state — final chance to persist data
• Release listeners — unregister callbacks
• Free memory — nullify references to prevent leaks
transitions
What is the typical lifecycle flow when user presses home?
click to reveal
answer
Resumed → Inactive → Paused

User presses home: app goes to Inactive (brief transition), then to Paused (background). If the user opens the app again: Paused → Inactive → Resumed.
transitions
When does Detached happen?
click to reveal
answer
Detached happens when:
• The system kills the app process to free memory
• The user swipes the app away from recent apps
• The app is being destroyed for any reason

It is the final state — no further transitions. The app must be fully recreated.
listener
What is AppLifecycleListener?
click to reveal
answer
A class that lets you listen to lifecycle changes via callbacks. Instead of checking the state manually, you register callbacks: onResume, onPause, onHide, onDetach, onStateChange. The callbacks fire automatically when the state changes.
listener
What callbacks does AppLifecycleListener provide?
click to reveal
answer
onResume — app enters Resumed state
onPause — app enters Paused state
onHide — app becomes invisible
onDetach — app is being destroyed
onStateChange — generic callback, receives the state name
onExitRequest — system requests app to close
listener
Why use AppLifecycleListener instead of checking state manually?
click to reveal
answer
Automatic — callbacks fire when state changes, no polling needed
Cleaner code — centralised lifecycle handling in one place
Reliable — you never miss a state change
Multiple callbacks — you can handle each state differently
platform
How does Paused differ between Android and iOS?
click to reveal
answer
Android: Paused — app may still be partially visible (split-screen mode).
iOS: Paused — app is fully hidden, no part of the UI is visible.

This means on Android you should not assume the user can't see anything when Paused.
exam trap
What is the most common exam mistake about lifecycle states?
click to reveal
answer
Confusing Inactive with Paused

Inactive = brief transition, app still partially visible, no input
Paused = fully in background, not visible (or barely on Android)

Also: Detached ≠ Paused. Detached = app is destroyed. Paused = app is alive in background.
