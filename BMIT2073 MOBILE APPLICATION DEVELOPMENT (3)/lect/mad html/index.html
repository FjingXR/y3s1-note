About this subject ▶

BMIT2073 — Mobile Application Development (MAD) is a third-year semester subject that teaches you how to build real mobile apps from scratch using Flutter and the Dart programming language.

Flutter is Google's cross-platform UI toolkit — with a single Dart codebase you can ship apps to Android, iOS, the web, and desktop. It does not use platform-native widgets; instead it paints every pixel itself via the Skia rendering engine, giving you consistent UI and full control across devices.

Across the 11 chapters you'll move from the fundamentals — the mobile OS landscape, app types (native vs hybrid vs web), Dart syntax — through building user interfaces, managing state, and handling data, all the way to location services, device sensors, and finally packaging and publishing your app to the stores.

These study guides are built directly from the lecture notes and structured for revision. Use the ← back links inside each chapter to return here, and the open → buttons to jump into a topic. Click the arrow above to hide this intro anytime.

Chapter 1 — Introduction & Dart
opencode

Introduction to Mobile App Development

Mobile OS ecosystem, native vs hybrid vs web apps, Flutter architecture, reactive UI paradigm, development tools comparison.

Module 1.1
▶ mini cheatsheet
  • Native = one platform, best performance, highest cost (separate codebases).
  • Cross-platform = one codebase, good balance (Flutter, React Native).
  • Web/PWA = runs in browser, cheapest, limited device access.
  • Flutter renders its own UI via Skia — does NOT use native widgets.
  • 3 layers: Framework (Dart) → Engine (C++/Skia) → Embedder (platform).
  • Declarative UI: you describe what the UI should be; Flutter rebuilds automatically.
  • Layout: constraints go down (parent limits child), sizes go up (child reports size).
  • 3D game → choose Native (best GPU/performance access).

Module 1.2
▶ mini cheatsheet
  • Dart is open-source, general-purpose, OOP, strongly typed.
  • Entry point: main() — every Dart program starts here.
  • Data types: int, double, num, String, bool.
  • var = type inferred; nullable types add ? after the type.

Chapter 2 — App Lifecycle
study guide

App Lifecycle & Navigation

Routes & Navigator stack, shared state with Provider, deep linking, AppLifecycleState, AppLifecycleListener.

Module 2
▶ mini cheatsheet
  • A route = a screen = a widget. Android = Activity, iOS = ViewController.
  • Navigator manages routes as a stack — push adds on top, pop removes from top.
  • Deep linking = open a specific screen from a URL. Android = App Links, iOS = Universal Links.
  • 4 lifecycle states: Resumed (visible), Inactive (transition), Paused (background), Detached (destroyed).
  • Resumed → play video. Inactive → pause game. Paused → save data. Detached → clean up.
  • AppLifecycleListener has callbacks for each state (onResume, onPause, onDetach).
  • Pass data via constructor injection. Return data via Navigator.pop(context, data).
  • Shared data across screens → use Provider (ChangeNotifier + Consumer).

User Interfaces

Basic widgets, Stateless vs Stateful, Material & Cupertino, single/multi-child layouts, Sliver widgets, performance tips.

Module 3.1
▶ mini cheatsheet
  • Widget = building block of Flutter UI. Immutable,描述 what the UI should be.
  • StatelessWidget = no mutable state; StatefulWidget = has mutable state via setState().
  • 9 basic widgets: Text, TextField, Icon, Image, ElevatedButton, Row, Column, Stack, Scaffold.
  • Row = horizontal layout; Column = vertical layout. Both use MainAxisAlignment + CrossAxisAlignment.
  • Single-child: Center, Align, Padding, SizedBox, Expanded, Flexible.
  • Multi-child: Row, Column, Stack, Wrap, ListView, GridView.
  • Material = Material Design (Android); Cupertino = iOS-style widgets.
  • Sliver widgets for scrollable lists — SliverList, SliverGrid — lazy loading, better performance.

claude design

Platforms, Themes & Design

Colors & Material Design, typography, internationalization, adaptive design, accessibility, screen support.

Module 3.2
▶ mini cheatsheet
  • Color: 4 ways — Color(0xFFRRGGBB), Colors.blue, Color.fromARGB(), Color.fromRGBO().
  • ColorSwatch: 100–900 number system; Colors.blue[400] = specific shade.
  • Style vs Theme: Style = per-widget; Theme = app-wide defaults. Theme cascades down.
  • Flutter applies styling: local style → nearest Theme → default. Local always wins.
  • ThemeData has colorScheme and textTheme — the 2 main properties.
  • 2 ways to override theme: ThemeData (app-wide) or Theme widget (局部 override).
  • 4 font style properties: fontFamily, fontSize, fontWeight, fontStyle.
  • Google Fonts: add package → GoogleFonts.latoTextTheme() for app-wide font.

claude design

State Management & Navigation

Ephemeral vs app state, Provider pattern, tab/drawer navigation, dialogs, snackbar, navigation principles.

Module 3.3
▶ mini cheatsheet
  • Ephemeral state = local UI state (e.g. page scroll); App state = shared/global (e.g. user login).
  • Provider: ChangeNotifier + ChangeNotifierProvider + Consumer pattern.
  • 4 Provider setup steps: 1) Create model, 2) Wrap with Provider, 3) Consumer reads, 4) call notifyListeners().
  • Consumer rebuilds only its subtree; context.read() for one-off reads (no rebuild).
  • 5 navigation principles: Back, Up, Bounce, Replace, Pop-and-push.
  • Tab: TabController + TabBar + TabBarView. Fixed tabs = known count; Scrollable = dynamic.
  • Drawer: Scaffold → drawer property → Drawer widget. Use for 5+ navigation destinations.
