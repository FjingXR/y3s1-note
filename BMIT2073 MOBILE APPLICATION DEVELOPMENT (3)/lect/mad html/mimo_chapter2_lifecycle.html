Chapter 2 — Routes, Navigation & App Lifecycle

How Flutter moves between screens, passes data, and manages app lifecycle states. Built from lecture slides, designed for quick revision.

MODULE 2

What are routes?

In Flutter, every screen (page) you see is called a route. A route is just a widget. When you move from one screen to another, you are navigating between routes.

Routes across platforms

PlatformWhat a "screen" is calledExample
FlutterRoute (widget)MaterialPageRoute
AndroidActivityMainActivity
iOSViewControllerUIViewController
Key idea

In Flutter, you do not create "Activities" or "ViewControllers". You create a Widget and the Navigator shows it as a new screen.

How it works

To navigate, you tell Flutter which widget to show next. Flutter wraps it in a MaterialPageRoute (which adds the slide animation) and pushes it onto the Navigator stack.

Practice questions

Q1. What is a route in Flutter?
A route is a screen/page in the app. In Flutter, a route is a widget shown by the Navigator.
Q2. What is Android's equivalent of a Flutter route?
An Activity on Android, or a ViewController on iOS.
Navigation

The Navigator stack

The Navigator keeps screens in a stack (like a pile of plates). When you open a new screen, it goes on top. When you go back, the top screen is removed.

Screen 1 Home
→
Screen 2 Detail
→
Screen 3 Settings

↑ Screen 3 is on top (visible). Screen 2 is behind it. Screen 1 is at the bottom. When Screen 3 pops, Screen 2 becomes visible again.

Key Navigator methods

MethodWhat it does
Navigator.push()Adds a new screen on top of the stack
Navigator.pop()Removes the top screen (goes back)
Navigator.popUntil()Goes back to a specific screen in the stack
Navigator.pushReplacement()Replaces current screen instead of adding on top
Stack rule

You can only see the top screen. You can only go back by popping the top. You cannot jump to the middle of the stack directly (use popUntil for that).

Practice questions

Q1. What data structure does Navigator use to manage screens?
A stack (last-in, first-out). Screens are pushed on top and popped from the top.
Q2. What happens when you pop a screen from the Navigator stack?
The top screen is removed from the stack. The previous screen becomes visible again.
Navigation

Navigator.push() and Navigator.pop()

Navigator.push() — what happens

  1. You call push with the target widget (the new screen).
  2. Flutter wraps it in a MaterialPageRoute (adds slide animation: left-to-right on Android, bottom-to-top on iOS).
  3. The new screen is placed on top of the stack. It becomes the visible screen.
  4. The previous screen stays in the stack underneath — it is not destroyed.

Navigator.pop() — what happens

  1. You call pop on the current screen.
  2. Flutter removes the top screen from the stack.
  3. The screen underneath becomes visible again.
  4. If you pop the last screen, the app closes (or returns to the OS).
Common mistake

Forgetting to pass context to pop(). Without it, Flutter does not know which Navigator to use.

Practice questions

Q1. What happens when you push a new screen onto the Navigator stack?
Flutter wraps the new screen widget in a MaterialPageRoute (adds animation) and places it on top of the stack. The new screen becomes visible. The previous screen stays underneath.
Q2. What animation does MaterialPageRoute provide on Android?
A slide from left to right. On iOS, it slides from bottom to top.
Data Passing

Send data between screens

You can pass data from one screen to another by sending it through the constructor of the target widget.

Main Screen (sender)

Creates the target widget and passes data as a constructor argument when pushing.

Flow: create data → pass to constructor → push screen

Detail Screen (receiver)

Accepts the data in its constructor and uses it to display content.

Flow: receive data in constructor → use it in build → display to user

1
Main screen creates a Todo object with data (title, priority).
2
Main screen calls Navigator.push() and passes the Todo object to the detail screen's constructor.
3
Detail screen receives the Todo in its todo parameter.
4
Detail screen displays todo.title and todo.priority.
Exam tip

Data passing uses constructor injection — you pass the data as a parameter when creating the widget. This is the simplest and most common way to pass data in Flutter.

Practice questions

Q1. How does Screen A pass data to Screen B when navigating?
Screen A passes the data as a constructor argument when creating Screen B during the push. Screen B receives the data in its constructor and uses it to display content.
Q2. What is the technical name for this data passing pattern?
Constructor injection — passing data as constructor parameters.
Data Passing

Return data from a screen

Sometimes you need the second screen to send data back to the first screen (e.g. user selects an item and the first screen needs to know which one).

1
Screen A pushes Screen B using Navigator.push().
2
Screen B does some work (e.g. user picks an option).
3
Screen B calls Navigator.pop(context, 'Returned Data') — the second argument is the data to send back.
4
Screen A receives the data using .then() callback.

How Screen B sends data back

Screen B calls pop with a second argument — the data to return. The data is sent back to Screen A.

How Screen A receives the data

Screen A waited for the push call to complete. When Screen B pops, the push call finishes and returns the data Screen B sent. Screen A can then use that data.

Alternative: .then() callback

Instead of waiting, Screen A can also register a callback that runs when the push completes. Both approaches achieve the same result — Screen A gets the data back.

Practice questions

Q1. What method sends data back from Screen B to Screen A?
Screen B calls pop with a second argument — the data to return. The data is sent back to Screen A.
Q2. How does Screen A receive the returned data?
Screen A waits for the push call to complete. When Screen B pops, the push call finishes and returns the data. Screen A can also use a .then() callback.
State Management

Shared state with Provider

When multiple screens need to share the same data (e.g. a shopping cart), passing data via constructors becomes messy. Provider solves this by giving all screens access to the same data.

How Provider works — the flow

1
ChangeNotifier — a class that holds the shared data. When data changes, it calls notifyListeners() to alert all screens.
2
ChangeNotifierProvider — placed at the top of the app. It creates the ChangeNotifier instance and makes it available to all screens below it.
3
Consumer — any screen wraps its UI in a Consumer. The Consumer listens for changes and rebuilds the UI automatically when data updates.
Key insight — the flow

ChangeNotifier holds data → Provider shares it at the top → any Consumer screen reads it → when data changes, notifyListeners() triggers → all Consumers rebuild. This is how multiple screens stay in sync without passing data through constructors.

Provider vs Navigator passing

Navigator passing = one-time, point A to point B. Provider = shared, real-time, any screen can read/write the same data.

Practice questions

Q1. When should you use Provider instead of passing data via Navigator?
When multiple screens need to share and update the same data (e.g. shopping cart, user profile, theme settings).
Q2. How does a ChangeNotifier tell all screens that data has changed?
It calls notifyListeners(). This alerts all Consumer widgets, and each one rebuilds its UI with the updated data.
Navigation

Deep linking

Deep linking lets users open a specific screen inside your app directly, instead of always starting from the home screen. For example, clicking a link opens the app directly at a product page.

Deep linking by platform

PlatformTermHow it works
AndroidApp LinksURL maps to a specific Activity/screen via intent filters in AndroidManifest.xml
iOSUniversal LinksURL maps to a specific screen via associated domains in the Apple app site association file
Fluttergo_router / auto_routeFlutter packages that handle URL parsing and map URLs to routes
Exam tip

Deep linking is like a shortcut. Instead of: Open app → Home → Menu → Product → Item, the user clicks a link and goes directly to: Open app → Item.

Practice questions

Q1. What is deep linking?
The ability to open a specific screen inside an app directly from a URL or link, skipping the home screen.
Q2. What is the Android term for deep linking?
App Links.

State details

Resumed, Inactive, Paused, Detached.
Q2. When the user switches to another app, which state does your app enter?
First Inactive (brief transition), then Paused (background).
Q3. Give one task example for the Paused state.
Pause music, save user progress, stop GPS tracking, close network connections.
Lifecycle

AppLifecycleListener

Flutter provides the AppLifecycleListener class to watch for lifecycle changes. You can run code when the app enters each state.

How it works

  1. Create an AppLifecycleListener when your app starts (in initState).
  2. Give it callback functions for the states you care about (onResume, onPause, onDetach, etc.).
  3. When the app enters a lifecycle state, the matching callback runs automatically.
  4. Always dispose the listener when your app is destroyed to free resources.

Available callbacks

CallbackRuns when
onShowApp becomes visible
onResumeApp enters Resumed state (visible + active)
onHideApp becomes invisible
onInactiveApp enters Inactive state (brief transition)
onPauseApp enters Paused state (background)
onDetachApp enters Detached state (being destroyed)
onRestartApp restarts after being detached
Exam tip

You don't need to memorize every callback name. Just know that AppLifecycleListener exists and has callbacks for each lifecycle state (onResume, onPause, onDetach, etc.).

Practice questions

Q1. What class do you use to listen to lifecycle changes in Flutter?
AppLifecycleListener — it has callbacks for each lifecycle state.
Q2. What callback runs when the app goes to the background?
onPause runs when the app enters the Paused state (background). onHide runs when the app becomes invisible.

Exam revision — know these facts

  • A route in Flutter = a screen = a widget. Android calls it Activity, iOS calls it ViewController.
  • The Navigator manages routes as a stack. Push adds on top, pop removes from top.
  • Deep linking opens a specific screen directly from a URL. Android = App Links, iOS = Universal Links.
  • The app has 4 lifecycle states: Resumed (visible), Inactive (brief transition), Paused (background), Detached (destroyed).
  • Use AppLifecycleListener with callbacks (onResume, onPause, onDetach) to react to lifecycle changes.
  • When app enters Paused → pause videos, save data. When app enters Detached → clean up resources.
  • Pass data between screens via the target widget's constructor (constructor injection).
  • Return data from a screen using Navigator.pop(context, data).
  • For shared data across screens, use Provider (ChangeNotifier + Consumer pattern).

Common mistakes to avoid

  • Confusing Inactive (brief transition) with Paused (background) — Inactive is temporary, Paused is sustained.
  • Not disposing resources (videos, streams, listeners) when the app goes to Paused or Detached.
  • Assuming deep linking works automatically — you must configure it per platform.
  • Forgetting that lifecycle state examples are worth marks — always give at least one task per state.
