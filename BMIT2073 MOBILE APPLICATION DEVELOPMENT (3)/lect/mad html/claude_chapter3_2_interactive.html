MODULE 3.2

Colors and ColorSwatch

Lecture 3.2, slide 3–8

Flutter has ready-made color constants, and you can also build your own colors from numbers.

Q1. What are the 4 ways to create a Color in Flutter? EXAM

Answer

See table below — all 4 create the same type of result: a Color object.
ConstructorExampleUse Case
Color()Color(0xFFCE4EC)Direct hex value (ARGB in hex form)
Color.fromARGB()Color.fromARGB(0xFF, 0x42, 0xA5, 0xF5)Alpha, Red, Green, Blue as separate hex/int values
Color.fromRGBO()Color.fromRGBO(66, 165, 245, 1.0)Red, Green, Blue (0–255) + Opacity (0.0–1.0)
ColorSwatchMaterialColor(0xFF007AFF, {...})A group of related colors under one theme (shades/tints)

Q2. How does the 100–900 number system work for color swatches?

Answer

Most swatches go from 50 to 900 in steps of 100. Smaller number = paler (lighter) color. Bigger number = darker color. Accent swatches (like redAccent) only have 100, 200, 400, 700.

Q3. What is ColorSwatch used for?

Answer

ColorSwatch groups many colors around ONE base color theme. Useful for making a palette with different shades, tints, and tones — and you can also give colors custom names (keys) instead of just numbers.

ColorSwatch myColorSwatch = MaterialColor(0xFF007AFF, { 50: Color(0xFF007AFF), 500: Color(0xFF007AFF), 'arrow': Color(0xFF20877E), 'border': Color(0xFF20877E), }); Container( color: myColorSwatch[500], // access a specific shade ) border: Border.all( color: myColorSwatch['border'], // access by custom key )

More practice

Which is paler: Colors.blue[100] or Colors.blue[800]?
Colors.blue[100] — smaller number means paler/lighter color.
What values does Color.fromRGBO() need?
Red, Green, Blue (each 0–255), and Opacity (0.0 to 1.0).
What values does an accent swatch (e.g. redAccent) have?
Only 100, 200, 400, and 700 — not the full 50–900 range.
Material Design

Styles, Themes & ThemeData EXAM

Lecture 3.2, slide 10–18

Material Design is Google's open-source design system — the default look for a Flutter app. A theme lets you set colors and fonts once, and use them everywhere.

Q1. What is the difference between a Style and a Theme?

Answer

A Theme applies to the whole App. A Style applies to just one Widget. Style is more specific and local; Theme is shared and global.

1
Theme — set once for the whole App (colors, fonts).
2
Style — override just for one Widget, if needed.

Q2. In what order does Flutter apply styling? EXAM

Answer

  1. Style applied directly to the specific widget
  2. Theme that overrides the immediate parent theme
  3. Main theme for the whole app

In short: closest/most specific style wins.

Q3. What are the 2 main properties of ThemeData?

colorScheme

Defines the colors used across the whole app (primary, secondary, background, etc.).

textTheme

Defines text styling across the whole app (headlines, titles, body text sizes/weights).

MaterialApp( title: appName, theme: ThemeData( useMaterial3: true, colorScheme: ColorScheme.fromSeed( seedColor: Colors.purple, brightness: Brightness.dark, ), textTheme: TextTheme( displayLarge: const TextStyle(fontSize: 72, fontWeight: FontWeight.bold), bodyMedium: GoogleFonts.merriweather(), ), ), )
// using the theme inside a widget Container( color: Theme.of(context).colorScheme.primary, child: Text( 'Text with a background color', style: Theme.of(context).textTheme.bodyMedium!.copyWith( color: Theme.of(context).colorScheme.onPrimary, ), ), )

Q4. What are the 2 ways to override a theme? EXAM

Answer

  • Create a unique ThemeData instance — makes a totally new theme, ignoring the parent's theme.
  • Extend the parent theme — keeps most of the parent theme, but changes only a few properties.

Both use the Theme widget to wrap the part of the app you want to change.

Theme( data: ThemeData( colorScheme: ColorScheme.fromSeed(seedColor: Colors.pink), ), child: FloatingActionButton( onPressed: () {}, child: const Icon(Icons.add), ), )
Where to find it

Chapter_3_Merged.pdf — slides 10 to 18 (Material Design, Styles and Themes, ThemeData, Override a Theme).

More practice

Which wins: a style set directly on a widget, or the app's main theme?
The style set directly on the widget wins — it's the most specific, applied first in the styling order.
How do you read the current theme's colors inside a widget's build method?
Theme.of(context).colorScheme.primary (or any other colorScheme/textTheme property).

Q3. What is Google Fonts, and how do you use it?

Answer

Google Fonts (fonts.google.com) is a website where you can try/test many fonts. In Flutter, you use the google_fonts package (from pub.dev) to apply these fonts directly in your TextTheme.

textTheme: TextTheme( titleLarge: GoogleFonts.oswald(fontSize: 30, fontStyle: FontStyle.italic), bodyMedium: GoogleFonts.merriweather(), displaySmall: GoogleFonts.pacifico(), )

Q4. Serif vs Sans-Serif — which is easier to read? EXAM

Serif

Has small lines/strokes (feet) at the ends of letters. Traditional, often used in print/books.

Sans-Serif

"Sans" = without. No extra lines at letter ends. Cleaner, simpler shapes.

Exam answer

Sans-Serif is generally considered easier to read on screens (mobile/digital), especially at small sizes, because its shapes are simpler and clearer on low-resolution displays. Serif can be better for large printed text.

Where to find it

Chapter_3_Merged.pdf — slides 21 to 25 (Fonts and Typography, Google Fonts Tester, Serif vs Sans-Serif).

More practice

Name the 4 font style properties.
Typeface, Size, Style, Weight.
Which TextTheme category is used for the biggest, most eye-catching text (like a splash screen title)?
Display (e.g. displayLarge) — the biggest category, meant for short, important text.
Design for Everyone

Internationalization (i18n) EXAM: Q1a

Lecture 3.2, slide 27–41

Design for Everyone = making your app usable by as many people as possible, no matter their age, ability, language, or device. One big part of this is internationalizing your app.

Q1. What are the 3 methods under "Design for Everyone"?

Answer

  1. Internationalizing
  2. Supporting different screens
  3. Make apps more accessible

Q2. What does "internationalizing" mean, and what 5 things does it involve? EXAM

Answer

Internationalizing = making your app adapt to different languages, cultures, and regions.

  • Language Translation
  • Generate Localization Delegates
  • Date, Number and Currency Formatting
  • Text Direction (e.g. left-to-right vs right-to-left)
  • Cultural Nuances (small cultural differences)

Q3. What are the setup steps for internationalization? EXAM

1
Add flutter_localizations and intl to pubspec.yaml.
2
Create .arb files (Android Resource Bundle) — one file per language, holding key-value text pairs.
3
Set localizationsDelegates in your MaterialApp/CupertinoApp (Material, Widgets, Cupertino delegates).
4
Set supportedLocales — the list of languages/regions your app supports.
// en.arb { "helloWorld": "Hello, world!", "greeting": "Hello, {name}!" } // fr.arb { "helloWorld": "Bonjour, le monde!", "greeting": "Bonjour, {name}!" }
return const MaterialApp( localizationsDelegates: [ GlobalMaterialLocalizations.delegate, GlobalWidgetsLocalizations.delegate, GlobalCupertinoLocalizations.delegate, ], supportedLocales: [ Locale('en'), // English Locale('es'), // Spanish ], home: MyHomePage(), );

Q4. What is the ISO 639 language code format? EXAM

Answer

Format: [language code]_[country code].

LanguageLanguage CodeCountry CodeFull Code
US EnglishenUSen_US
Malay (Malaysia)msMYms_MY
Chinese (China)zhCNzh_CN
final myCurrency = Intl.NumberFormat('#,##0.00', 'ms_MY'); symbol = myCurrency.currencySymbol; output = myCurrency.format(total);
Why formatting matters

Dates, numbers, and currency are written differently in different countries (e.g. 27/07/2026 vs 07/27/2026, RM vs $). Using intl formatting keeps this correct automatically, based on locale.

Where to find it

Chapter_3_Merged.pdf — slides 27 to 41 (Design for Everyone, Internationalizing, Setting up, Language Translation, ISO Codes).

More practice

What file type holds translated text for each language?
.arb files (Android Resource Bundle) — e.g. en.arb, fr.arb.
What is the full ISO code for Malay spoken in Malaysia?
ms_MY — language code "ms" (Malay) + country code "MY" (Malaysia).
Which Flutter function/class marks a string as needing translation?
Intl.message() — wraps the string, e.g. Text(Intl.message('Hello, world!')).

Supporting different screens

Lecture 3.2, slide 42–58

Phones come in many sizes and screen qualities. Your app must adapt to all of them.

Q1. What are the screen size and density categories? EXAM

Answer

See table below — Size describes physical screen size; Density describes pixel sharpness.
Size CategoryDensity CategoryExample
SmallLow (ldpi)Older / cheap small phones
NormalMedium (mdpi)Standard phone
LargeHigh (hdpi)Bigger phone / small tablet
xLargeExtra high (xhdpi)Tablet, high-end phone

Resolution examples: HD (720×1280), FHD (1080×1920), QHD (1440×2560).

Q2. What 2 tools help with adaptive design (responsive layouts)?

Flexible / Expanded

Distribute leftover space among child widgets automatically — so layout adapts to any screen width.

FittedBox

Scales images/content to fit the available space, keeping proportions correct.

Q3. How do you provide different image resolutions for different screens? EXAM

1
Create an assets/images/ folder.
2
Add subfolders/files for each density: logo.png, logo@2x.png, logo@3x.png.
3
List them in pubspec.yaml under assets:.
4
Call Image.asset('assets/images/logo.png') — Flutter auto-picks the best resolution for the device.

Q4. How does Flutter handle screen orientation?

Answer

Use MediaQuery.of(context).orientation to check Portrait or Landscape, and build a different layout for each. Use SystemChrome.setPreferredOrientations() to force a fixed orientation (e.g. lock to portrait).

body: MediaQuery.of(context).orientation == Orientation.portrait ? PortraitLayout() : LandscapeLayout(),

Q5. What is minSdkVersion vs targetSdkVersion? EXAM

minSdkVersiontargetSdkVersion
MeaningLowest Android API level your app supportsHighest API level your app is designed/tested for
Why set itTo support more (older) devicesTo use the latest OS features
Display cutouts

Newer phones have screen cutouts: Tear Drop, Notch, Punch Hole (middle/left/right). Your layout should avoid placing important buttons/text under these cutouts.

Design for Everyone

Making apps more accessible EXAM: Q1a

Lecture 3.2, slide 59–74

Accessibility = users of all abilities can navigate, understand, and use your app.

Q1. What are the 3 accessibility considerations? EXAM

Answer

  1. Navigation
  2. Readability
  3. Guidance and Feedback

Q2. Navigation — what 3 things help accessible navigation?

1. Support screen readers

Use the Semantics widget to give labels for screen readers (tools that read the screen aloud for blind/low-vision users).

Semantics( label: 'This is a button', child: ElevatedButton( onPressed: () {}, child: Text('Click Me'), ), )

2. Easy-to-follow navigation

Support keyboard/gesture input. Avoid UI that fades/disappears too fast. Keep a flat navigation structure (not too many levels deep).

3. Large touch targets

Minimum size 48 × 48 px. Minimum space between elements: 8dp.

Q3. Touch target size — Do vs Don't EXAM

✓ Do

Buttons at least 48×48 px, with clear spacing. Finger fits inside comfortably; edges give visual feedback when tapped.

✗ Don't

Buttons too small or squeezed together. User might miss the tap or press the wrong button by mistake.

Q4. Readability — what helps users read your app better?

Answer

  • Adequate color contrast — text color must stand out clearly against the background.
  • Don't rely on color alone — e.g. don't show "Going" only in green and "Can't go" only in red; add icons/text too, for colorblind users.
  • Accessible media — give controls to pause/stop video/audio, and provide transcripts/captions.

Q5. Guidance and Feedback — what makes controls "clear and discoverable"?

Answer

  • Interactive controls need text labels, tooltips, or placeholder text — so users know what they do.
  • Be consistent in naming — use the same word for the same action everywhere in your app.

Q6. What is gesture navigation (Android 10 / API 29)?

Answer

Android 10 supports fully gesture-based navigation (swipe instead of buttons). Your app should extend content edge-to-edge and handle any conflicting gestures properly.

Where to find it

Chapter_3_Merged.pdf — slides 59 to 74 (Accessibility: Navigation, Readability, Guidance and Feedback).

More practice

What is the minimum recommended touch target size?
48 × 48 pixels, with at least 8dp spacing between elements.
Which widget helps screen readers understand a widget's purpose?
Semantics widget, using its "label" property.
Why is it bad design to show status using ONLY color (e.g. red = error)?
Colorblind users may not tell the colors apart. Always add extra cues like icons, text, or patterns alongside color.

Chapter 3.2 — full cheat sheet

  • Color: Color(), Color.fromARGB(), Color.fromRGBO(), ColorSwatch. Swatch 50–900: smaller = paler.
  • Theme = app-wide. Style = widget-level. Order: widget style → parent theme override → main app theme.
  • ThemeData has 2 main parts: colorScheme (colors) and textTheme (text styling).
  • Theme override: new ThemeData instance, OR extend parent theme — both via the Theme widget.
  • Font style = Typeface + Size + Style + Weight. TextTheme categories: Display, Headline, Title, Label, Body (each Small/Medium/Large).
  • Sans-serif = easier to read on screens; serif = better for large print text.
  • Design for Everyone = 3 methods: Internationalizing, Supporting different screens, Accessibility.
  • i18n setup: pubspec.yaml → .arb files → localizationsDelegates → supportedLocales.
  • ISO code format: [language]_[country], e.g. ms_MY.
  • Screen categories: Small/Normal/Large/xLarge size × ldpi/mdpi/hdpi/xhdpi density.
  • minSdkVersion = oldest devices supported. targetSdkVersion = latest features tested.
  • Accessibility = 3 parts: Navigation (Semantics, 48×48px touch targets), Readability (contrast, not color-only), Guidance (clear labels, consistent terms).
