native
What is a native app?
click to reveal
answer
A native app is built for one specific platform using that platform's official language and SDK. Android = Kotlin/Java + Android SDK. iOS = Swift/Objective-C + iOS SDK. Each platform gets its own separate codebase.
native
What are the pros of native apps?
click to reveal
pros
Best performance — direct access to GPU, CPU, full hardware acceleration
Full API access — every platform feature available immediately
Best UX — uses native UI widgets, feels "right" on each platform
Platform updates — new OS features available on day one
3D games & AR — only native gives full graphics pipeline control
native
What are the cons of native apps?
click to reveal
cons
Separate codebases — Android and iOS need different code, double the work
Highest cost — need two teams or two skill sets
Longest development time — building and maintaining two apps
Harder to keep consistent — features may drift between platforms
native
When should you choose native?
click to reveal
answer
When you need:
• 3D games — full GPU access, custom rendering
• AR/VR apps — camera + sensor + GPU pipeline
• Maximum performance — real-time audio/video processing
• Platform-exclusive features — e.g. iOS HealthKit, Android NFC
hybrid
What is a hybrid / cross-platform app?
click to reveal
answer
A hybrid app uses one codebase to deploy to multiple platforms. Examples: Flutter (renders own UI via Skia), React Native (bridges to native widgets). Write once, run everywhere. Good balance of cost and quality.
hybrid
What are the pros of hybrid apps?
click to reveal
pros
One codebase — write once, deploy to Android + iOS (and web/desktop)
Lower cost — one team, one skill set
Faster development — single build pipeline
Consistent UI — same look across all platforms
Hot reload — instant preview of changes (Flutter)
hybrid
What are the cons of hybrid apps?
click to reveal
cons
Performance gap — not as fast as native for heavy tasks (3D, real-time)
Platform updates lag — new OS features may take time to reach the framework
Bridge overhead (React Native) — communication between JS and native adds latency
Larger app size — bundles framework runtime into the app
Not ideal for 3D games — no direct GPU pipeline control
hybrid
When should you choose hybrid?
click to reveal
answer
When you need:
• Both Android + iOS — with limited budget/time
• Standard UI apps — social media, e-commerce, dashboards
• Fast iteration — startup MVPs, prototypes
• Consistent branding — same design across platforms
web
What is a web / PWA app?
click to reveal
answer
Runs in the browser. A regular web app uses HTML/CSS/JS. A PWA (Progressive Web App) adds offline support, push notifications, and installability — but still runs in a browser sandbox.
web
What are the pros of web / PWA apps?
click to reveal
pros
Cheapest to build — one codebase, works everywhere with a browser
No installation — users just visit a URL
Instant updates — deploy once, all users get the new version
SEO friendly — search engines can index the content
Lowest barrier — works on any device with a modern browser
web
What are the cons of web / PWA apps?
click to reveal
cons
Limited device access — camera, GPS, sensors, file system restricted
No app store presence — harder for users to discover
Lower performance — browser adds overhead, no native GPU access
Offline limits — PWA offline mode is limited vs native caching
No push notifications on iOS Safari (limited support)
web
When should you choose web / PWA?
click to reveal
answer
When you need:
• Content-driven sites — blogs, news, portfolios
• Lowest cost — tight budget, quick launch
• Broad reach — any device, any browser
• SEO matters — search engine visibility is critical

flutter
Why does Flutter NOT use native widgets?
click to reveal
answer
Flutter renders via Skia (its own engine) — it paints every pixel itself. This gives pixel-perfect consistency across Android/iOS/web. If it used native widgets, the UI would look different on each platform.
trade-off
What is the core trade-off between these 3 approaches?
click to reveal
answer
Performance & access vs cost & reach

Native = max performance, max cost
Hybrid = good balance, medium cost
Web = max reach, min performance

There is no "best" — it depends on your app's needs.
