Question 1(a)

(i) Construct a table to briefly compare between native, hybrid and mobile web apps based on the following FIVE (5) criteria: Development cost · App performance · Distribution method · Access to device features · Code maintenance. (15 marks)

(ii) Select the most appropriate mobile app type (native, hybrid or mobile web) for a highly interactive 3D mobile game. Briefly justify your selection. (2 marks)

(i) The comparison table

Criteria Native Hybrid Mobile Web
Development costHighLowLow
App performanceFastDepends on network speedDepends on network speed
Distribution methodApp storesApp storesNone (just a URL)
Access to device featuresWideLimitedVery limited
Code maintenanceMultiple codebase (one per OS)Single codebaseSingle codebase

(ii) 3D mobile game → choose Native

Why native
  • 3D games need fast performance (high FPS, no lag) — native gives full hardware speed
  • Games need deep device access — GPU, sensors, haptics — native has wide access
  • Hybrid/web app performance depends on network, not good for real-time 3D graphics

  • 5 criteria to compare: cost, performance, distribution, device access, maintenance

  • Rule of thumb: heavy graphics/performance app → Native. Budget/simple app → Web/Hybrid

MODULE 3.1 Lecture 3.1, slide 48 "Stateless vs Stateful Widget" 4 marks

Question 2(a)

Provide TWO (2) differences between stateless and stateful widgets. (4 marks)

Two differences, side by side

StatelessWidget

  • Fixed appearance and behaviour
  • Does not hold any internal state
  • Example: GreenFrog, Frog
class GreenFrog extends StatelessWidget { ... }

StatefulWidget

  • Maintains its own state — reacts to user input / data change
  • Manages state through a State object (uses setState())
  • Example: YellowBird, Bird
class Bird extends StatefulWidget { ... }

MODULE 3.2 Lecture 3.2, slides 30–41 "Internationalizing" 4 marks

Question 2(c)

Present any TWO (2) methods of internationalising mobile apps for adapting to different languages, cultures and regions. Briefly elaborate your answers. (4 marks)

2 methods (pick any 2 of the 5 listed in slides)

1. Language Translation

Create .arb files (Android Resource Bundle) for each language, e.g. en.arb, fr.arb. Mark translatable text using Intl.message().

2. Generate Localization Delegates

Import flutter_localizations package, set localizationsDelegates and supportedLocales in MaterialApp.

3. Date, Number, Currency Formatting

Format values based on locale, e.g. Intl.NumberFormat('#,##0.00','ms_MY') to show correct currency symbol.

4. Text Direction

Support left-to-right (LTR) and right-to-left (RTL) reading direction depending on language.

(A 5th method exists: Cultural Nuances — adapting content/images to fit local culture.)

MODULE 3.3 Lecture 3.3, slides 17–23 "Navigation Principles" 5 marks

Question 2(e)

Identify the FIVE (5) navigation principles (explanation is not required). (5 marks)

The 5 navigation principles

1️⃣
Fixed start destination — every app has one fixed screen it always starts from
2️⃣
Navigation state is a stack of destinations — top of stack = current screen
3️⃣
Up and Back are identical within your app's task — both pop the current screen off the stack
4️⃣
The Up button never exits your app — it disappears at the start destination
5️⃣
Deep linking simulates manual navigation — jumping straight to a detail screen still follows the normal navigation path
Where to find it

Chapter_3_Merged.pdf (3.3) — slide 17 (list of 5 principles), slides 18–23 (each explained with diagrams).

Practice — similar questions

P1. What is at the "top" of the navigation stack?
  • The current screen the user is looking at
P2. When does the Up button disappear from the app bar?
  • At the app's fixed start destination — because Up must never exit the app
P3. True or False: pressing Back and pressing Up always do different things.
  • False — within your app's own task, Up and Back behave identically

Quick recap — Q2e

  • 1. Fixed start destination
  • 2. Stack of destinations
  • 3. Up = Back (within app task)
  • 4. Up never exits app
  • 5. Deep linking = simulated manual navigation
